## Mechanism recovered from PoC

1. **Ownership and activation.** `BuilderHandler` owns a backreferenced root Data Bag, one shared `_` segment and named builder segments; it attaches the handler and segment to each builder before `create()` (P `js/dom/src/builder-handler.js:81-175`). Builders keep Source below `_sourceroot/_root_`, which is backreferenced before child creation (P `js/dom/src/builder-base.js:68-95`). `create()` prepares logic and subscribes the Source root for insert/update/delete only when an application is present (P `js/dom/src/builder-base.js:638-659`); `activate()` renders first, populating the reader index, then subscribes the Data root and enables `live()` (P `js/dom/src/builder-handler.js:161-175`). This ordering prevents the Data observer from reacting to initial render. Tests: basic mounted render and reactive patch (P `js/dom/tests/embryo.test.js:76,95,112,132`). Untested here: subscription race across partial activation failure.

2. **Pointer resolution and index.** `SourceBagNode.pointerType` recognizes `^` and `=`, excluding `==`; `pointers()` returns only `^` in attributes or scalar node value (P `js/dom/src/source-bag.js:128-150`). `absDatapath` removes the marker, preserves `?attr`, qualifies by builder volume, resolves relative ancestor `datapath`, `#parent`, `#FORM`, `#ANCHOR`, and `#id` (P `js/dom/src/source-bag.js:172-277`); the path tests cover each form (P `js/dom/tests/abs-datapath.test.js:33-172`). `runtimeValues` reads both `^` and `=` fresh from Data, but registers only eligible `^` readers, including the legacy grid/chart `structpath` exception; data widgets exclude most internal pointers (P `js/dom/src/builder-base.js:242-280`). `pointerMap` is absolute path → Set of Source nodes (P `js/dom/src/builder-handler.js:187-229`). Relevant readers match exact node, a subscribed descendant of a replaced container, or subscribed ancestor of a changed child, with per-node dedup (P `js/dom/src/builder-handler.js:248-278`). Tests: selective reader patch (P `js/dom/tests/embryo.test.js:112-148`), `=` fresh on peer trigger (P `js/dom/tests/local-logic.test.js:65`), expansion anchor rather than per-row registration (P `js/dom/tests/component.test.js:137-153`). `?attr` is stripped for path relationship checks (P `js/dom/src/builder-handler.js:254`), but the PoC does not itself distinguish a value-only update from an attribute-only update at this point; compare legacy below. Rebinding when an *ancestor `datapath` or symbolic target changes* has no explicit index rekey path in the inspected `_onUpdAttrs` logic, so it needs a focused regression test before claiming coverage.

3. **Data event order.** The Bag observer receives `ins`, `upd_*`, `del`, `pathlist`, and `reason`; PoC ignores `reason === 'autocreate'`, computes insert/delete paths by appending `node.label`, then obtains relevant readers (P `js/dom/src/builder-handler.js:572-581`). It runs component row rules first, ordinary data elements second, view readers last; synchronous writes reenter the cascade (P `js/dom/src/builder-handler.js:582-607`). A view node equal to `reason` skips its own rerender (anti-echo); providers are not skipped by this check (same lines). Controller receives `{kw: event, trigger_reason: 'node'|'container'|'child'}` (P `js/dom/src/builder-handler.js:286-300`; `js/dom/src/logic/runtime.js:199-213`), directly asserted by P `js/dom/tests/local-logic.test.js:138`. `fired` is exposed through `SourceBagNode.fireEvent/FIRE` and passes to Bag `setItem` (P `js/dom/src/source-bag.js:288-310`); the installed PoC Bag clears the stored value silently afterward (P `js/dom/node_modules/genro-bag-js/src/bag-node-container.js:268-270`). Crucial gap: the observed Bag event payload has no `fired` field (`.../bag.js:588-599`); test event-vs-state semantics before promising legacy equivalence. `reason` is retained on Bag events; Source `setRelativeData` defaults to `true`, `PUT` uses `false` (P `js/dom/src/source-bag.js:288-310`).

4. **Logic lifecycle and update order.** Newly inserted branches are queued by Source events, then prepared once as a batch before a live flush, excluding already removed nodes (P `js/dom/src/builder-base.js:205-219,331-345`; `js/dom/src/logic/runtime.js:37-53`; P `js/dom/tests/branch-preparation.test.js:14,68,79`). Preparation runs setters, defaults, service registration, `^` provider indexing, then `_on_start` providers. Startup formulas are topologically ordered by destination dependency and cycles reject explicitly (P `js/dom/src/logic/runtime.js:53-125`; P `js/dom/tests/local-logic.test.js:14,82`). Formula bindings resolve again on every execution; `dataFormula` writes destination, controllers execute synchronously and guard self-recursion, with `_triggerpars` and `_reason` in controller bindings (P `js/dom/src/logic/runtime.js:161-213`; P `js/dom/tests/reactive-logic.test.js:38,60,80,166`; P `js/dom/tests/branch-preparation.test.js:115`). Inside `live()`, formulas queue by provider identity and drain FIFO after branch preparation, reading settled values; controllers stay synchronous. Requeue limit 50 reports a livelock (P `js/dom/src/builder-handler.js:280-345,789-849`). Tests explicitly cover chaining, dedup/cycle, cancellation of removed queued formula (P `js/dom/tests/reactive-logic.test.js:80,166`; `js/dom/tests/local-logic.test.js:121`). Row-component rules are *a separate expansion concern*: they compile row-relative and shared triggers and dispatch by row coordinates, with synchronous row controllers (P `js/dom/src/builder-handler.js:347-569`; P `js/dom/tests/component-rules.test.js:114,131,164`). They are coupled to collection expansion, not a prerequisite for ordinary binding recovery.

5. **Source mutation, render queue and cleanup.** Source deletion removes event owners and recursively unregisters pointers; value replacement removes old scalar pointer or old Bag subtree pointers; attr update removes old `^` pointers (P `js/dom/src/builder-base.js:327-390`; `js/dom/src/builder-handler.js:197-229`). Source insert/delete queue child-path ops, updates queue node replacement, and data-element declarations remain DOM transparent (P `js/dom/src/builder-base.js:331-359`). `live()` nests, collects touched paths, prepares surviving branches, drains formulas, then optimizes and flushes final state; it clears queues in `finally` (P `js/dom/src/builder-handler.js:789-849`). Optimizer nets per path, covers descendants with ancestor patches, coalesces dense cells/rows for component expansion (P `js/dom/src/builder-handler.js:662-787`). `renderNodes` maps optimized entries to target patches, with full render when partial patches are unsupported (P `js/dom/src/builder-base.js:692-720`). Removed providers are taken out of pending formula queues; delayed calls, feedback, resolver/server/store/database ownership and pointer entries are released (P `js/dom/src/builder-handler.js:197-215`; `js/dom/src/logic/runtime.js:235-242`). Focused tests: provider removal, queued cancellation, inserted/removed branch (P `js/dom/tests/local-logic.test.js:100,121`; `js/dom/tests/branch-preparation.test.js:31,79`). **No PoC Source `freeze()/unfreeze()` contract is present in these inspected core files**; `live()` is batching, not Source freeze. Do not conflate them.

## Current Gramlot and published dependency comparison

Current `GramlotRenderer` requires `BuilderBase`, `SourceBag`, `SourceBagNode` and subscribes to Source Bag events (G `js/src/renderer/gramlot-renderer.js:1,14-33,49-54`). It renders inserted branches in Source sibling order, updates scalar value/attrs in place when possible, otherwise rebuilds a branch; it owns mount records, reverse cleanup, references, queued reentrant Source events, and idempotent disposal (G `js/src/renderer/gramlot-renderer.js:218-365`). `freeze(node)` ignores Source render events under a mounted branch and `unfreeze(node)` rebuilds current Source once; deleted detached nodes are traced via mount-record parent (G `js/src/renderer/gramlot-renderer.js:182-215`). These are implemented Source lifecycle capabilities and covered by G `js/tests/renderer.test.js:50-80` and `js/tests/freeze.test.js:17-149`; they do **not** establish Data reactivity or PoC `live()` semantics.

Published Builder `runtimeValues` resolves `^`/`=` from a flat Data Bag at render, supports resolver values, templates and `_wdg` carried attrs, but explicitly does not install reactive subscriptions (G `js/node_modules/@jsr/genro__builders/src/builder-base.js:14-16,450-485`). Published Source nodes expose `pointers()`, relative/symbolic `absDatapath`, and `SET/GET/PUT/FIRE` with `reason`/`fired` arguments (G `js/node_modules/@jsr/genro__builders/src/source-bag.js:79-104,108-205,210-239`). Unlike PoC named-volume paths, upstream `absDatapath` produces paths for its flat builder Data Bag (same file, `:108-130`). Published Bag requires `setBackref()` to subscribe, propagates typed `ins/upd_*/del` with `pathlist` and `reason` (G `js/node_modules/@jsr/genro__bag/src/bag.js:601-668,696-724`), and resets fired values silently (G `js/node_modules/@jsr/genro__bag/src/bag-node-container.js:268-270`). The package `BagNode.setValue` emits only on value/attribute change; attr updates have their own `upd_attrs` event (G `js/node_modules/@jsr/genro__bag/src/bag-node.js:164-209,306-348`). There is no present core Data reader index, Data event dispatcher, provider cascade, or Data `live()` batch in G `js/src/renderer/gramlot-renderer.js`; any proposed port must assign those responsibilities explicitly rather than copying the PoC `BuilderHandler` whole.

## Legacy cross-check and explicit deviations

Legacy GenroPy dynamically indexes stable absolute paths in a trie and places movable pointer/symbolic paths in a floating set; it snapshots target subscriptions before dispatch because callbacks can rebuild the tree (L `genro_src.js:28-103`). Its trigger relationship distinguishes node/container/child and filters value-only vs attr-only changes, `?attr`, fired child events, `autocreate`, and anti-echo for view nodes (L `gnrdomsource.js:129-181`). PoC uses a flat Map scan and only strips `?attr` for relationship checks; this is an implementation simplification and possible semantic gap, not an approved incompatibility. Legacy `fired` travels in trigger payload (L `gnrbag.js:321-325`), while the installed Bag event payload inspected above does not. Legacy Source freeze defers rebuild while cleaning detached discarded children immediately (L `genro_src.js:167-207`; `gnrdomsource.js:43-55`); current Gramlot Source freeze has mount-record cleanup on thaw/removal but must be separately checked for discarded-child resources during freeze. Legacy index also preserves subscriptions whose effective target moves; PoC static absolute registration needs rekey verification.

## Bounded recovery questions and test gaps

**Fundamental to first binding contract:** declare the Data Bag ownership/flat-path convention; `^` reactive vs `=` passive reads; path relationship including `?attr` and value/attr event filtering; Data event ordering and anti-echo; direct input writeback origin; Source replacement/ancestor `datapath` rebinding; formula/controller execution and startup rules if their declarations are in the same scope; lifetime cleanup; reason/fired semantics; batching visibility. Tests should distinguish exact, ancestor, descendant and unrelated paths, node value and attribute changes, Source parent replacement, moving paths, provider removal, nested writes and disposal. Legacy is nearly ideal behavioral reference under constitution §5; deviations require an explicit review record.

**Coupled but separable:** PoC named builder volume/shared `_`, partial remote patch protocol, target serials, component row/cell expansion and density optimizer, grid/chart `structpath`, store/database/RPC cancellation, recipe policy/default service, forms, and DOM widget-specific presentation. They rely on reactivity but are not needed to prove the ordinary binding path. This distinction does not erase their existing PoC behavior or authorize silently dropping it from later scoped ports. No alternative input representations or permissive fallbacks should be introduced (constitution §§13–14).

**Evidence limits:** Existing PoC tests cover many ordinary paths cited above, but this audit found no focused proof for `?attr` event selectivity, dynamic ancestor/symbolic `datapath` reindexing, `fired` in subscriber payload, and cleanup timing of discarded Source under freeze. Current G tests cover Source mount/mutation/freeze and static pointer resolution, not Data-to-view reactive propagation. A read-only review cannot establish runtime compatibility; a bounded port needs executable tests in Gramlot and an explicit destination review.
