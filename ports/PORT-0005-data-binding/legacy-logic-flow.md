## 1. Declaration, mount, subscription

Python legacy declares `dataFormula(path, formula, **kwargs)` and `dataController(script=None, **kwargs)` as Source children; the Python surface explicitly expects variable bindings via `^` (subscribe) and `=` (read) (GenroPy `gnrpy/gnr/web/gnrwebstruct/dojo11.py:86-110`; `gnrpy/gnr/web/widgets/genro.py:18-53`). The JavaScript Source handler lists both among `datatags`; `stripDataNode` routes them through `moveData` during node build, and `GnrDomSourceNode.build()` calls strip before ordinary widget building (`L/genro_src.js:120-125,559-605`; `L/gnrdomsource.js:961-996`). Thus logical provider nodes are Source-owned yet do not create ordinary widget DOM. This is a call-chain observation, not a claim that all aliases/legacy tags transfer.

`moveData` first calls `registerNodeDynAttr(false)`, which resets prior subscriptions and marks only `^` attributes as dynamic; `=` is read later but does not subscribe (`L/genro_src.js:602-605`; `L/gnrdomsource.js:906-926,1160-1174`). It then marks provider type. `_init` causes one immediate `setDataNodeValue()` during this setup. Without `_init`, a `path` is ensured in Data through `getDataNode(path, true)` but no provider evaluation occurs solely for that action (`L/genro_src.js:644-652`). `_onStart` adds synthetic `^gnr.onStart` dynamic attr and, if numeric, supplies `_delay`; `_onBuilt` schedules a separate after-build execution (`L/genro_src.js:658-700`). Finally `_setDynAttributes()` installs handles (`L/genro_src.js:702`; `L/gnrdomsource.js:1202-1215`). **Do not collapse `_init`, `_onStart`, `_onBuilt` into one startup flag.** P instead prepares setters, defaults, then indexes providers and runs opt-in `_on_start` providers, ordering startup formulas by dependency (`P/js/dom/src/logic/runtime.js:37-125`). This is an intentional PoC shape, not legacy startup parity. Existing P tests assert late-branch initialization and formula ordering (`P/js/dom/tests/branch-preparation.test.js:14,27,79,93`; `js/dom/tests/local-logic.test.js:82`).

## 2. Dynamic dependency dispatch and path relation

Legacy `_setDynAttributes()` adds each `^` declaration to `GnrTriggerIndex`: stable absolute paths go into a path-segment trie; pointer/symbolic paths that can move go into a floating set and are re-evaluated per event (`L/gnrdomsource.js:1202-1289`; `L/genro_src.js:28-103`). `genro.dataTrigger` publishes to this index (`L/genro.js:1601-1653`). Index dispatch snapshots targets before calling `node.trigger_data(attr, kw)` because a callback may rebuild and unregister them (`L/genro_src.js:76-103`). `getTriggerReason` compares bound path to event path and reports `node`, `container`, or `child`; it screens `autocreate`, value-vs-attribute changes, and `?attr`, with special fired handling (`L/gnrdomsource.js:129-158`). `trigger_data` ignores a fired child relationship, otherwise sends providers to `setDataNodeValue(kw.node, kw, trigger_reason)`; it skips self-origin only on the view update route (`L/gnrdomsource.js:160-181`). Accordingly a controller may still react to a write it causes; legacy has no general controller recursion guard in this call path.

P's reader index maps absolute path to Set of Source nodes and matches node/container/child with dedup, but strips `?attr` before relationship comparison without legacy's explicit value/attribute filtering (`P/js/dom/src/builder-handler.js:187-229,248-278`). On Data event it runs component rules, then data-element readers, then view readers; only view readers perform anti-echo (`P/js/dom/src/builder-handler.js:572-608`). P tests prove formula recomputation, cascades and controller trigger payload (`P/js/dom/tests/reactive-logic.test.js:38,80`; `js/dom/tests/local-logic.test.js:138`). No located test establishes moving symbolic/ancestor `datapath` reindexing or `?attr` selectivity in P. These are material legacy behaviors, not optional optimizations.

## 3. Invocation, arguments, conditions, evaluation

For a provider trigger, `setDataNodeValue` reads current attrs, interprets `_delay` (`auto` disables it) and debounces a prior pending timeout; `_ask` may defer execution through a dialog (`L/gnrdomsource.js:218-265`). `setDataNodeValueDo` filters `autocreate` and `_userChanges` when the relation is not `node` (`L/gnrdomsource.js:267-285`). It strips control attrs, resolves optional output `path`, obtains formula text from `formula` or controller code from `script`, and builds standard arguments `_node`, `_triggerpars={kw,trigger_reason}`, `_reason` (`L/gnrdomsource.js:286-327`). For each remaining attr it calls `getAttributeFromDatasource` **at execution time**, adding a named argument and entry to `_kwargs`; this reads both `^` and `=` fresh, so passive inputs can affect a run triggered by a reactive peer (`L/gnrdomsource.js:326-375,596-640`). `==` inline expressions evaluate against other attrs, with recursion avoidance for other formula attrs (`L/gnrdomsource.js:608-634`). Subscription and direct invocation kwargs can add arguments in the same path (`L/gnrdomsource.js:338-374`).

`_if` evaluates in that argument environment. If false with no `_else`, execution returns without writing; if `_else` exists, its expression/script replaces the main body (`L/gnrdomsource.js:376-390`). For a formula, legacy prefixes `return ` to the expression; for a controller it uses the script body. `funcCreate` expands `GET/SET/PUT/FIRE` macros and compiles/evaluates with the Source node as `this` (`L/gnrdomsource.js:476-488`; `L/gnrlang.js:1663-1684,1829-1850`). A formula with an output path writes the result with `setRelativeData`, re-entering Data triggers; a controller may also return a result if it was given an output path (`L/gnrdomsource.js:476-488`). Ordinary nested writes are synchronous within this call chain; exact global order is influenced by legacy Source/after-build pending queues (root agent is auditing that queue separately). Legacy `_if/_else`, `_userChanges`, `_ask`, `_onBuilt` and subscription-driven invocation are established code behavior but their public inclusion in a first Gramlot contract requires an owner-scoped decision; do not silently emulate or silently erase them.

P exposes `dataFormula({destination,formula,...bindings})` and `dataController({func,...bindings})`; it excludes own fields and resolves bindings fresh (`P/js/dom/src/builder-base.js:429-466`; `js/dom/src/logic/runtime.js:136-158,181-213`). Formula accepts callable, named method, function text or JS expression; controller accepts callable/named/function text/script. P executes controllers synchronously with `_triggerpars` and `_reason`, guards direct reactive recursion, and during `live()` deduplicates formula execution until flush, draining FIFO with a requeue limit (`P/js/dom/src/logic/runtime.js:193-213`; `js/dom/src/builder-handler.js:280-345,789-849`). P `_delay` debounce is tested (`P/js/dom/tests/provider-actions.test.js:15-39`); removal cancels timers (`:132-146`). P does not implement legacy `_if/_else`, `_init`, `_onBuilt`, `_userChanges` in the inspected `LogicRuntime`, and renames legacy `path/script/_onStart` to `destination/func/_on_start`; these are concrete deviations to review, not missing method fallbacks.

## 4. SET / PUT / FIRE, reason, fired, nested effects

Legacy macros expand `GET path`, `SET path = expr`, `PUT path = expr`, and `FIRE path [= expr]` to the Source node's read/write methods (`L/gnrlang.js:1663-1684`). `SET` uses default `reason=true`; `PUT` passes `reason=false`, which suppresses the Bag trigger; `FIRE` passes `fired=true` (`L/gnrlang.js:1668-1684`; `L/gnrdomsource.js:579-595`). Legacy `fireItem` emits a fired event then silently resets stored value to null (`L/gnrbag.js:1718-1722`); existing-node `setValue` includes `fired` in the trigger payload (`L/gnrbag.js:321-325`). The source write can reenter provider dispatch synchronously. The event's `reason` is a doTrigger/origin value, and view anti-echo compares it with the source node (`L/gnrdomsource.js:175-180`); default Source `setRelativeData` uses true unless caller overrides (`L/gnrdomsource.js:579-595`). Avoid calling false a mere "origin label": it suppresses the write's trigger in legacy.

P `SourceBagNode.SET/PUT/FIRE` maps to `setRelativeData` with default true/false/fired (`P/js/dom/src/source-bag.js:288-310`), while the installed P Bag silently clears a fired value (`P/js/dom/node_modules/genro-bag-js/src/bag-node-container.js:268-270`). However its Bag event payload contains `reason` but no `fired` field (`P/js/dom/node_modules/genro-bag-js/src/bag.js:588-599`); this is a **dependency gap for full legacy fired-trigger metadata**, not permission for a Gramlot consumer workaround. Same published Bag API in G (`G/js/node_modules/@jsr/genro__bag/src/bag.js:601-668`), and Source node macros remain (`G/js/node_modules/@jsr/genro__builders/src/source-bag.js:218-239`). The PoC tests establish SET/GET/PUT execution and formula cascade (`P/js/dom/tests/reactive-logic.test.js:60,80`), but not a legacy-equivalent `fired` event payload.

## 5. Replacement, removal, rebinding

Legacy Source rebuild first tears down discarded content, unsubscribes its dynamic handles, and then builds current content; deletion calls `_onDeleting` and recursive subscription cleanup (`L/genro_src.js:240-258,337-404`). Dynamic attr re-registration resets prior handles before installing current ones (`L/gnrdomsource.js:906-926,1160-1174,1202-1215`). Legacy frozen branches still clean discarded content while postponing rebuild (`L/genro_src.js:167-207`). This is relevant to provider lifetime: a detached formula/controller must stop responding and release pending work. P Source events delete pointers recursively, cancel pending formulas and delayed calls, and dispose provider-owned services (`P/js/dom/src/builder-base.js:331-390`; `js/dom/src/builder-handler.js:197-215`; `js/dom/src/logic/runtime.js:235-242`), with targeted removal tests (`P/js/dom/tests/local-logic.test.js:100,121`; `js/dom/tests/provider-actions.test.js:132`). P does not have legacy's floating re-evaluation path for moving symbolic bindings in the inspected index; no claim of complete rebinding is supported.

## 6. Current Gramlot boundary and required verification

The published Builder has static `dataSetter/dataFormula/dataController` definitions and computes them during `BuilderBase.create()` in Source document order; its formula uses `attr.func`, and `runtimeValues` reads bindings at that execution, without reactive subscriptions (`G/js/node_modules/@jsr/genro__builders/src/builder-base.js:73-80,450-485,534-574,646-652`). Gramlot's own authoring builder overrides `create()` and `computeLogic()` so browser declarations are inert during authoring (`G/js/src/builder/gramlot-builder.js:4-17`). Current `GramlotRenderer` observes Source insert/update/delete and has mount/freeze/disposal; it does not observe Data or run provider triggers (`G/js/src/renderer/gramlot-renderer.js:14-33,182-248,352-365`). A destination contract including formulas/controllers must therefore assign Data subscriptions, provider installation and teardown, event payload, cascade ordering, and batched formula semantics to Gramlot or an explicitly approved connected adapter—not infer them from static Builder execution or modify installed Builder/Bag code inside Gramlot (repository AGENTS.md §14).

Minimum meaningful destination tests: startup with `^` and `=` dependencies; formula and controller both responding to exact/ancestor/descendant Data changes; nested SET and silent PUT; FIRE trigger payload and final null state; current argument reads and `_triggerpars/_reason`; `_if/_else` only if explicitly scoped; deterministic order for chained formulas/controllers; provider removal during pending work; Source replacement and movable datapath rebinding; self/cross cycle failure; two isolated application instances; and cleanup during Source freeze. Established legacy details must be recorded as preserved or intentionally different in the bounded port; absence from P tests is not evidence that they are irrelevant.
