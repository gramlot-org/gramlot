## PoC facts: authoring and initialization

The teaching page declares `root.data('.name','Ada')`, greeting and tone, then `^.name` input and preview readers (`src/gramlot/showcase/demo/pages/hello_binding.py:4-16`). The showcase places a `data_root` Bag declaration and scopes the visible branch with `datapath='data_root'` (`src/gramlot/showcase/__init__.py:116-130`). Thus both `setup(data)` direct writes and declarative Source data setters exist; the latter is not a separate transport payload.
- JS page builder supplies `root=this.source` and opts into `root.data(...)` alias (`js/pages/src/builder.js:17-25`; `js/dom/src/source-bag.js:379-388`). `BuilderHandler` owns a segmented root Bag with `_` shared segment, creates each builder's named segment and assigns `instance.data` before `instance.create()` (`js/dom/src/builder-handler.js:85-90,132-154`). Its `activate()` renders then subscribes insert/update/delete on Data (`:161-175`). `BuilderBase.create()` invokes setup, main, and logic branch preparation (`js/dom/src/builder-base.js:638-657`); Source `dataSetter` logic writes its destination and attributes into Data (`js/dom/src/logic/runtime.js:45-77,181-192`; branch preparation is called by `js/dom/src/builder-base.js:638-657`). Source data elements render transparently (`js/dom/src/renderer/base.js:63-82`). PoC Application exposes handler Data and wrapped Source (`js/dom/src/application.js:133-139`). Inspect `js/dom/src/logic/runtime.js` for branch seeding, repeat/remount rules before specifying destination semantics.
- PoC pointer contract distinguishes `^` reactive and `=` passive; `pointers()` indexes only `^` (`js/dom/src/source-bag.js:128-149`). `absDatapath`, relative scopes and symbolic anchors are at `:172-277`; `getRelativeData/setRelativeData` at `:280-309`. `BuilderBase.runtimeValues()` reads current Data (`js/dom/src/builder-base.js:240-283`). ## PoC facts: writeback

- `Application.mountBuilder()` attaches the target, activates handler, then installs delegated listeners; `dispose()` removes recorded listeners and disposes handler (`js/dom/src/application.js:62-108`). `mutate(elementId,value)` resolves an owned Source node by writeback map or target ID; destination comes from the node's `value` or `checked` pointer, not a client supplied path (`:149-205`). Both reactive `^` and passive `=` pass `pointerType`, so both are writable in this PoC code path although only `^` registers a reactive reader. Missing pointer throws.
- Data write occurs inside `handler.live()`, passes the Source node as Bag event reason, and records the current value on the target (`js/dom/src/application.js:157-176`). Handler skips that same reader on subsequent Data events (`js/dom/src/builder-handler.js:589-605`), preserving that input element during its own write. This is node identity suppression, not a general IME/caret policy.
- Delegated `input` and `change` listeners require element ID and `data-value-pointer` or `data-checked-pointer`, then recover Source node by ID (`js/dom/src/application.js:222-266`). `checked` reads boolean `el.checked`; other controls read `el.value`. Default is native `change` (described as blur timing). `live` overrides `updateOn`; truthy live selects `input`, false selects `change`; `updateOn='input'` selects `input`; slider `intermediateChanges` can select input. `commitOnChange` overrides to change. Forms can intercept commit; symbolic editing ignores input. Custom shadow widgets may use `gnr-set` events with a detail pointer (`:268-340`), a separate PoC path that must not be assumed part of native writeback.
- `_typedValue()` returns null for empty non-text dtype unless widget null state preserves empty; otherwise non-text strings remain raw (`js/dom/src/application.js:207-220`). Native checkbox writes boolean. The file's header at `:17-21` is stale: later code implements reason anti-echo but still no full TYTX dtype decode. Widget null behavior and IME-related `KeyboardEvent.isComposing` are tested at `js/dom/tests/input-null.test.js:24-84`; this is widget-specific and is not evidence that the generic delegated input handler suppresses composition events. `js/dom/src/components/control-tools.js:34` checks composing for Escape only.
- `js/dom/tests/writeback.test.js:43-132` verifies pointer hook, mutate/peer update, same-origin element identity, change vs input timing and live flag. `js/dom/tests/embryo.test.js:95-136` verifies pointer preservation/index and reactive patch. `js/dom/tests/input-null.test.js:24-84` verifies widget null/empty, typed widget values, read-only/disabled null suppression. Additional adjacent tests inspected via search: `js/dom/tests/local-logic.test.js:65-80` (passive formula read), `js/dom/tests/sliders-defaults.test.js:40` (slider/updateOn), `js/dom/tests/per-row-patches.test.js:179-188` (derived writeback cleanup). Their cases should be checked in detail before port scope is set.

## Destination facts and mismatch

- Installed published Builder JS gives each Builder a flat Bag (`js/node_modules/@jsr/genro__builders/src/builder-base.js:108-111`), `SourceBagNode.pointerType/pointers/absDatapath/setRelativeData` (`.../source-bag.js:71-91,108-140,208-239`), and `BuilderBase.runtimeValues()` that resolves current Data on render (`.../builder-base.js:448-485`). Its generic dataSetter compute path exists (`.../builder-base.js:553-590`). This is static read capability, not Gramlot reactive subscription or control writeback. Published `pointerType()` treats every leading `=` as a pointer (`.../source-bag.js:71-76`), unlike PoC's explicit `==` exception (`js/dom/src/source-bag.js:128-135`): literal leading `==` behavior differs.
- Gramlot Python/JS `create()` each call setup and main (`src/gramlot/page/builder.py:47-50`; `js/src/builder/gramlot-builder.js:16-17`), but host main/source return only serialized `builder.source` (`src/gramlot/server/host.py:119-139`; `js/src/adapters/host.js:80-91`). The browser creates its own `builder.data` with `main` Bag and mounts only typed Source (`js/src/gramlot.js:8-18,51-77`). A Python `setup(self.data)` value therefore is not delivered in this host contract. JS `setup` in a server-side page is likewise not transported. A Source `dataSetter` may be authored by generic grammar, but Gramlot does not run Source data-element initialization upon mounting; verify declaration acceptance per specific grammar before promising `root.data` syntax parity.
- `GramlotRenderer` subscribes to Source events only (`js/src/renderer/gramlot-renderer.js:14-33`). It invokes generic `RendererBase` for initial render (`:49-55,80-92`), but Source update calls `html.update(record,node)` without `runtimeValues` (`:281-297`). `HtmlElement.update` reads raw Source attributes and text (`js/src/view/html.js:101-139`). No Data event subscription, pointer index, DOM input/change listener, origin suppression or Data-to-DOM refresh exists in this path. Parent's manual JSDOM probe confirmed initial `^name` rendered Ada, subsequent Data change to Grace left DOM Ada while Source remained `^name` (report as externally supplied execution evidence, not this audit's test).
- `ports/PORT-0005-data-binding/README.md:20-50,80-103` correctly calls this proposed/unaccepted and lists unresolved initialization, passive writeback, null, timing, lifecycle and parity questions. Its `root.data` versus separate Data snapshot wording should be read as a design question, not a claim the PoC used separate mutually exclusive methods: PoC demonstrably supports both setup Data writes and Source setter declarations.

## GenroPy legacy reference (bounded)

- Legacy Python `data()` constructs a Source `data` child, converts dict to Bag, preserves Bag class marker and accepts `serverpath` (`/Users/gporcari/Sviluppo/Genropy/sourcerer_clones/genropy/genropy/gnrpy/gnr/web/gnrwebstruct.py:872-909`). Browser `moveData` resolves its path, extracts Source value, clears Bag backrefs, then writes Data if the node is absent or value non-null; it also handles server/shared extensions (`/Users/gporcari/Sviluppo/Genropy/genropy/gnrjs/gnr_d11/js/genro_src.js:602-632`). PoC `dataSetter` differs in spelling and implementation and should not be treated as semantic identity. Legacy `setData` delegates to Bag (`.../genro.js:1796-1799`). Source node `setAttributeInDatasource` defaults origin to this Source node; `trigger_data` skips updating that origin reader (`.../gnrdomsource.js:160-180,515-540`). `setRelativeData` resolves path and passes reason into Bag writes (`.../gnrdomsource.js:579-594`). Legacy has richer data provider/server paths than the bounded native control task; these are evidence, not automatic scope.

## Open questions for accepted contract

1. Initial Data authority across Python/JS HTTP and Worker: should Source data setters execute at mount, should host transport send page setup Data, or are both explicitly supported with an order/collision rule? State page isolation, remount, remote fragments and failure behavior. Do not presume either PoC or legacy behavior has been approved.
2. Choose binding address semantics (root namespace, nested relative paths, symbols, attribute paths, missing/deleted/parent replacement). Confirm that published Builder path API is sufficient; report dependency gaps to owning Builder.
3. Specify editable native controls and conversion: text/textarea/select/checkbox/range/number, null vs empty vs invalid, value vs checked and passive `=` write permission. Specify literal leading `^`/`=` escaping. PoC's generic handler lacks robust numeric conversion and generic IME suppression.
4. Define event timing, composition policy, focus/caret retention, origin/peer propagation, event echo and update scheduling with existing Source freeze/FIFO. State ownership/cleanup when Source changes, especially pointer/datapath mutation and removed controls.
5. Clarify distinction between static Builder resolution and Gramlot live binding; formatter/mask and data-node metadata are adjacent contracts, not implied by successful basic binding.
