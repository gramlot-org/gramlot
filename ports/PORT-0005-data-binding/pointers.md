## Important implementation gaps / conflict tests

1. Published Builder's treatment of `==` conflicts with both PoC and explicit owner decision. A focused Builder test should cover `==quantity * price` with `^.quantity` and `=.price`, peer expressions, cycles, and attribute/node-value behavior; do not recast it as a literal or path.
2. PoC's default segment prefix and `volume:` are absent in published Builder. Reconcile root/Data ownership before porting path output. The difference is observable even for `^field`: PoC test expects `main.field`; published Builder returns `field`.
3. Both symbolic resolvers drop `?attr` because of early return. Test `^#FORM.x?caption`, `^#ANCHOR.x?caption`, `^#id.x?caption` and decide whether attribute tails belong after symbolic resolution.
4. Legacy `#DATA`, `#WORKSPACE`, `#ROW`, aliases, `*S`, dynamic datapaths, and `../` are absent from PoC's Source resolver and from published Builder. They need separate scope/ownership review, not an assertion that only three symbolic forms exist.
5. Clarify whether `?=` Bag projections and `.?` normalization are required for Gramlot; `?=` is tested in legacy Bag, but no equivalent Source-binding test was found. The installed Bag's `../` traversal does not automatically make Source `absDatapath('../x')` equivalent.
6. PoC `js/dom/src/pointer.js` utility is `^`-only despite broader Source semantics. Audit callers before using it for any complete binding recovery.
7. No dedicated tests found for `=` reactive exclusion at Source-node value and attribute level, literal leading `^`/`=` handling, `?attr` updates through binding subscriptions, colon syntax errors/edge cases, symbolic `?attr`, or dynamic ancestor datapaths. The source and documents above are evidence of some behavior; absence of tests is not proof of desired semantics.
