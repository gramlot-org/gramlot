Repositories: GenroPy `/Users/gporcari/Sviluppo/Genropy/genropy` (paths prefixed `gnrjs/`), living PoC `/Users/gporcari/Sviluppo/gramlot/gramlot-poc` (paths prefixed `js/dom/`), installed published Builder and Bag `/Users/gporcari/Sviluppo/gramlot/gramlot/js/node_modules/@jsr/` (paths shown as package/src). ## Call flow and receiver

1. Legacy script text enters `funcCreate` (`gnrjs/gnr_d11/js/gnrlang.js:1829-1852`), which expands macros before compiling/evaluating and optionally binds scope. SourceNode methods are not the macro syntax. `getAttributeFromDatasource(attrname, autocreate, dflt)` reads own Source attributes, then `currentFromDatasource`; `^` and `=` call `getRelativeData`, whereas `==` evaluates with peer attributes (`gnrdomsource.js:596-640`). `registerNodeDynAttr` registers only `^` as reactive and records formula attributes (`:902-926`); `evaluateOnNode` resolves parameter dictionaries (`:933-947`).
2. Legacy `getRelativeData(path, autocreate, dflt)` calls `this.absDatapath(path)`; null path gives undefined. With autocreate, it calls `genro._data.getNode(path, false, autocreate, dflt)` before `getItem(path,null,null,{_sourceNode:this})`. Without autocreate it calls the same `getItem` without node creation (`gnrdomsource.js:548-574`). The `_sourceNode` context can reach resolvers; do not silently replace it with an ordinary Bag read. Published Builder's `getRelativeData(path, defaultValue=null, {autocreate=false})` creates via `setItem` only if a `getItem` read is null, then reads with `defaultValue` but no `_sourceNode` context (`@jsr/genro__builders/src/source-bag.js:210-216`). PoC's `getRelativeData(path, defaultValue=null)` is a simple `dataHandler.data.getItem(absDatapath(path), defaultValue)` (`js/dom/src/source-bag.js:282-286`).
3. Legacy `setRelativeData(path,value,attributes,fired,reason,delay,_kwargs)` defers with `setTimeout` when delay is truthy; otherwise defaults null reason to true, resolves path, and calls `genro._data.fireItem` if fired, setting `genro._firingNode=this` around that call; else calls `setItem` with `{doTrigger:reason,lazySet:true}` merged with `_kwargs` (`gnrdomsource.js:579-594`). The `_firingNode` assignment lacks try/finally. Legacy `fireEvent` uses `value || true`, so false/zero/empty become true (`:575-576`). Bag `fireItem` uses nullish-to-true and performs one triggered set plus silent reset to null (`gnrbag.js:1718-1721`). These two value defaults are observably different.
4. PoC `setRelativeData` calls its handler's Data Bag `setItem(absPath,value,attributes,'>',false,true,reason===null?true:reason,fired)`; `fireEvent` defaults only an omitted value to true; `SET/GET/PUT/FIRE` methods wrap it (`js/dom/src/source-bag.js:288-309`). Published Builder has near-identical wrappers but Data comes from `this.builder.data` (`@jsr/genro__builders/src/source-bag.js:53-54,218-239`). PoC `dataHandler` selects the source-root handler or builder handler (`js/dom/src/source-bag.js:99-112`). Published SourceBagNode's builder slot is set before insertion/subscriber publication (`@jsr/genro__builders/src/source-bag.js:35-54`), unlike PoC's initially-null slot (`js/dom/src/source-bag.js:43-49`). Ownership differences matter to detached/reparented nodes; no general equivalence was demonstrated.
5. Published Bag `setItem` positional signature includes independent `reason`, `fired`, `doTrigger` (`@jsr/genro__bag/src/bag.js:374-393`). Its node collection sends insert/update when `doTrigger` is true and, for `fired`, silently resets to null (`@jsr/genro__bag/src/bag-node-container.js:225-269`). Updates notify only when value/attrs changed (`@jsr/genro__bag/src/bag-node.js:164-210`); legacy `GnrBagNode.setValue` does not suppress an unchanged triggered update (`gnrbag.js:296-325`), though SourceNode's ordinary set uses `lazySet:true` and can suppress unchanged assignments (`:1834-1845`). Fire uses no `lazySet` and is expected to emit each time.

## Macro expansion is separate from methods

Legacy `gnrlang.js:1663-1692,1829-1843` transforms:

| Script text | Generated call |
| --- | --- |
| `GET path` | `this.getRelativeData('path')` |
| `SET path = expr` | `this.setRelativeData('path', expr)` |
| `PUT path = expr` | `this.setRelativeData('path', expr, null, false, false)` |
| `FIRE path = expr` / `FIRE path` | `this.setRelativeData('path', expr, null, true)` / `this.setRelativeData('path', true, null, true)` |
| `FIRE_AFTER path = expr` / `FIRE_AFTER path` | same fired call with 10 ms delay |

The macro regex accepts a limited token alphabet and is text substitution; inspect literal edge cases before treating it as a parser. `funcCreate` also expands PUBLISH. PoC/Builder expose method calls `this.GET/SET/PUT/FIRE` (`js/dom/src/source-bag.js:303-309`; published `src/source-bag.js:233-239`) but no equivalent legacy macro text compiler was found in these SourceNode flows. PoC tests use method calls (`js/dom/tests/reactive-logic.test.js:60-77`, `actions.test.js:14-16`). Thus accepting `this.SET(...)` does not establish acceptance of legacy `SET path = ...`.

**Material PUT mismatch:** legacy macro passes false as `doTrigger` via `setRelativeData` → `setItem` (`gnrlang.js:1673-1676`; `gnrdomsource.js:584-593`). PoC/Builder `PUT` pass `reason:false`, but leave Bag `doTrigger` at its true default (`source-bag.js:307`; published Bag `bag.js:387-393`). A focused published-Builder/Bag probe observed an insertion event for `PUT('quiet',7)` with reason false; it was not silent. This also applies by code inspection to the PoC's same positional call into Bag JS, subject to its installed Bag version.

## Path, symbolic context and subscription

- Legacy `absDatapath` strips `^`/`=`, delegates leading `#` to `symbolicDatapath`, treats `.` as current ancestor datapath, and climbs through own/parent SourceNodes while path remains relative. During the climb it invokes callable datapath, resolves pointer-valued datapath via `getAttributeFromDatasource`, resolves symbolic datapath, and stops with null when a dynamic datapath has no value (`gnrdomsource.js:721-752`). Unresolved relative logs/debugs rather than throwing (`:753-758`). It normalizes `.?` and collapses inner `#parent` via Bag path semantics (`:759-763`, `gnrbag_mixin.js:573-586`).
- Legacy symbolic heads include aliases in `genro._aliasDatapaths`, `#ROW` (widget current cell), `#WORKSPACE` (marked ancestor and optional path), `#DATA` (global Data root), generic nodeId, and `*S` Source path (`gnrdomsource.js:686-719`). Generic ID lookup delegates to `genro.nodeById`, which also handles slash child paths, FORM/ANCHOR ancestor lookup, global index and build-time fallback (`genro.js:2106-2142`). The method's behavior depends on the receiver and current Source tree, not merely string substitution.
- Legacy dynamic `^` subscriptions use `_stableTriggerPath`: `#parent`, movable symbols and dynamic datapath chains are floating; stable paths are indexed (`gnrdomsource.js:1202-1288`). Attribute path events distinguish `?attr`, fired and attribute updates (`:129-149`). This prevents stale subscription coordinates when aliases, row/workspace or ancestors move.
- PoC `absDatapath` supplies root-builder volume and optional `volume:`, resolves static relative chain, `#parent`, and `#FORM/#ANCHOR/#id`; unresolved relative and missing markers throw (`js/dom/src/source-bag.js:174-278`; `js/dom/tests/abs-datapath.test.js:33-175`). Published Builder implements the same three symbolic categories but no volume prefix/colon override (`@jsr/genro__builders/src/source-bag.js:109-205`). Neither resolver implements callable, pointer-valued or symbolic ancestor datapaths from legacy. Both drop `?attr` after leading symbolic dispatch because they split the tail then return from symbolic resolution without reattaching it.
- PoC's pointer map records a concrete absolute path at registration (`js/dom/src/builder-handler.js:217-227`) and broad matching strips `?attr` (`:250-275`). That is not equivalent to legacy's floating subscriptions for changing path coordinates. No test showing rebinding after a dynamically changing datapath or symbolic target was found.
- Published Bag handles `../` only in Bag traversal (`@jsr/genro__bag/src/bag.js:190-225`); Source `absDatapath('../x')` does not expand it. Its `?attr` write uses node collection query syntax (`bag-node-container.js:197-245`). Legacy Bag `?attr` write and autocreation are at `gnrbag.js:1755-1776`. The `?=...` projection observed in legacy Bag test `gnrjs/tests/bag_mixin.test.js:380-386` should be verified separately before claiming Source compatibility.

- Published Builder/Bag direct read-only probe: constructed a SourceBagNode prototype with a real published Bag as its Data, subscribed with `any`, called `PUT('quiet',7)` then `FIRE('command',42)` twice. Output in `/private/tmp/gramlot-legacy-flow-builder-probe.log`: PUT emitted `ins` with reason false; FIRE emitted `ins` then `upd_value`, each reason true; final command value null. This isolates method-to-Bag behavior but does not exercise a mounted Builder application or path resolver.

Open compatibility cases needing explicit tests in the owning layer: legacy dynamic/callable ancestor datapath and rebinding; `#ROW/#WORKSPACE/#DATA`, aliases, slash node IDs and `*S`; GET autocreate/resolver `_sourceNode`; relative `.?` and symbolic `?attr`; `PUT` event suppression; `FIRE` same-value repeat and false/zero/empty defaults; macro text compilation separately from methods; delayed fired writes and `_firingNode` context. No claim of complete compatibility follows from the passing focused tests.
