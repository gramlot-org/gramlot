# Adversarial component review — 2026-10-17

Owner request: review duplication, untidy/non-parametric code, inconsistencies and
arbitrary constants before building additional features. Scope: the input and
layout collections, Labelbox/FieldState, their renderer/adapter integration and
theme behavior. This is not an audit of the entire Gramlot codebase.

**Initial outcome: revision requested.** Existing successful tests establish useful
behavior, but do not justify considering this implementation fully cleaned up.
No production code was changed during this review. Correction directions below
are recommendations, not newly approved APIs or architectural amendments.

## Reproduced defects

### R1 · P1 — An ordinary textbox loses an uncommitted draft on label changes

Locations: `js/src/components/field-state.js:79`,
`js/src/components/inputs.js:75`, `js/src/renderer/gramlot-renderer.js:502`.

Reproduction: Data contains `name='Ada'`; textbox uses `value='^name'`,
`lbl_position='^position'` and the default live=False. Type `Grace`, without
committing, then change position from TL to L through Data. The displayed text
becomes `Ada`; the draft is lost. This is an ordinary editing scenario.

FieldState protects only rejected drafts. Plain text editors do not track the
uncommitted draft as typed/choice editors do. The formlet-specific
presentationOnly bypass protects a different route into the same operation.
The existing textbox caret test changes labels only after committing; the
validation test covers rejected input, not an uncommitted valid draft.

Correction direction: put the unchanged-value/presentation-update policy in the
shared editing/projection responsibility; cover textbox, textarea and password,
both direct label bindings and inherited formlet changes. Preserve real external
Data changes, IME and explicit value updates. Do not add another widget exception.

### R2 · P2 — Formlet repeats expression evaluation and refreshes unrelated children

Locations: `js/src/renderer/gramlot-renderer.js:68` and `:506`.

Each field walks its ancestor formlets, calls runtimeValues and evaluates their
expressions again. Any formlet projection then recursively projects every built
descendant, even when only columns changed and no inherited defaults changed.

Measured with three textboxes and one counted parent expression: **four parent
expression evaluations on mount; four more and three field projections when only
columns changes**. Besides avoidable work proportional to descendants and
ancestor depth, repeated expression evaluation violates the renderer's stated
once-per-projection intent and can produce inconsistent inherited values for
non-stable expressions. No wall-time performance claim is made from this probe.

Correction direction: reuse the declaring node's resolved defaults within a
projection and invalidate only affected descendant presentation. Verify nested
scopes, explicit overrides and Source insertion/removal before optimizing.

### R3 · P2 — readonly is silently ineffective on radioButtonText

Locations: `js/src/components/bases.js:182`, `js/src/components/inputs.js:54`.

ChoiceGroup reads `this.parameters.readonly`, but its shared descriptor declares
only disabled. CheckBoxText adds readonly locally; RadioButtonText does not.
The Builder accepts the extra attribute, but it never becomes a control parameter.

Measured: `radioButtonText(value='^x', values='a:Alpha,b:Beta', readonly=True)`
allows selecting Beta and changes Data from `a` to `b`. This is a descriptor/base
inconsistency, not a claim that every native input supports HTML readonly. The
documented limitation for standalone native-like radios/ranges/color is separate.

Correction direction: reconcile the shared group-state contract and declarations;
check both groups through Python grammar export and browser behavior.

### R4 · P2 — Formlet overrides its own inherited theme token

Location: `js/src/components/layout.js:39`.

The shadow stylesheet declares `:host{--gramlot-formlet-gap:8px 16px}`. This local
declaration overrides a token inherited from the page theme.

Measured in Chromium: root `--gramlot-formlet-gap:27px`; computed inner grid gap
remains `8px 16px`. Explicit host-level overrides can work, but the normal
page/theme inheritance does not.

Correction direction: use a fallback where the token is consumed, preserving
root theme values and explicit per-formlet gap overrides.

### R5 · P2 — Switch height is configurable, thumb geometry is not

Location: `js/src/components/inputs.js:29`.

The track uses --gramlot-switch-height; thumb width and checked offset still use
literal 1.4em. Measured in Chromium with height=40px and width=70px: the thumb is
approximately **13.59px wide and 34px high**, becoming an oval instead of scaling
with the track. The declared theme variable therefore controls only half the widget.

Correction direction: derive track/knob geometry from the same resolved sizing
tokens; verify minimum/maximum and checked positions in normal and touch modes.

### R6 · P3 — A successful copy retains the previous failure tooltip

Location: `js/src/components/layout.js:141`.

Reproduction: clipboard write rejects with `denied`, then the next write succeeds.
Status says `Copied TYTX` but the button title still says `Copy failed: denied`.
The success path restores text/status but never restores the title.

Correction direction: reset all copy feedback consistently on retry/success and
test permission failure followed by recovery, not just the failure alone.

## Structural duplication and cleanup findings

### R7 · Shared parameter projection has two implementations

`components/bases.js:28` and `components/layout.js:20` perform the same effective
parameter/default selection and consume the same parameter names. ChoiceGroup
also repeats inherited setPageContext and sameControlValue methods without adding
behavior. Centralize the genuinely common operation; input lifecycle and slotted
container construction should retain their separate responsibilities. A new
general component framework is not needed for this cleanup.

### R8 · Renderer behavior is coupled to concrete tags and grammar shape

`gramlot-renderer.js:71,75,506,511` knows the literal gramlot-formlet tag.
`view/controls.js:46,60` treats subTags='*' as the test for not having a value
adapter. `view/html.js:87` grants every such container readDataScope, with a
groupBox-specific error message, including formlet.

These conditions happen to fit the current two layout components, but conflate
child grammar, inheritance and Data-copy capability. This is architectural debt,
not a demonstrated failure of an already approved third-party container API.
Before expanding the collection, assign each existing responsibility explicitly;
any new descriptor/capability API needs a bounded naming/contract decision.

The new third project argument is also absent from gramlot-renderer.d.ts: either
keep that mechanism internal or align its declaration if it survives cleanup.

### R9 · Popup placement and sizing policy is repeated and already inconsistent

Independent geometry/cleanup lives in choice-editor.js:151, typed-editor.js:196,
field-state.js:47 and layout.js:107. Some surfaces close on scroll, another
repositions and the copy menu does neither while open. These behavior differences
are not automatically bugs: their purposes differ. The shared geometry, however,
has no consistent source of margins, viewport clamping and size limits.

Examples: choice popup CSS max-height=12rem is overwritten by an inline maximum
of 210px; the placement code also embeds 120px and 30px thresholds. Error fading
duplicates 200ms in CSS and JS. Group padding/radius/button sizes and vertical
slider inline 10rem/1.5rem geometry bypass the otherwise theme-driven controls.
These are maintenance/theme limitations, not evidence that every constant should
become a public parameter.

Correction direction: share narrowly scoped placement primitives where semantics
agree; retain distinct lifecycle policies where justified. Put visual defaults
behind existing/consciously named theme tokens, and give behavioral timings one
named source. Do not introduce a second popup state framework.

### R10 · Local-choice parsing is duplicated with different acceptance rules

`bases.js:115` and `choice-editor.js:196` both parse code:caption comma lists.
The editor filters empty entries and rejects empty IDs; the group accepts empty
codes and only rejects duplicates. This is an observed divergence, not a proposed
extension of supported input strings. Use one agreed parser/validation contract
for local options; keep selection cardinality and storage representation separate.

## Verification and limits

- 47 existing targeted tests passed: components, layout, typed editors, choices,
  calendar, input validation and touch mode, including Python grammar fixtures.
- `review-probes.mjs` reproduces R1/R2/R3/R6 against current source using jsdom.
  Its output is observational: it is not a regression suite asserting correct
  behavior. Run from the repository with
  `node ports/PORT-0011-formlet-group-box/review-probes.mjs`.
- `review-theme-probes.mjs` measures R4/R5 in Chromium against local gallery w21.
  Pass an absolute installed Playwright module path and gallery base URL.
  These DOM style overrides belong only to the isolated test page.
- R7–R10 are source-inspection findings. No full-suite, all-browser or performance
  qualification is claimed for this review. Existing successful tests do not cover
  the six reproduced cases as success/failure recovery or parameter-variation tests.
- Constants such as seven weekdays, the TYTX time epoch and the reference Monday
  used for weekday captions encode semantics; they are not arbitrary theme values.
  Existing boundary separation, native boolean binding, Source/Data ownership and
  portable grammar remain useful foundations; the findings do not call for a rewrite.

Recommended order: R1 and R2 (editing/projection), R3 (shared state), R4/R5
(effective theme parameters), R6 (copy recovery), then bounded R7–R10 cleanup.
Add regression tests for the failures before claiming the review closed. No new
component work or publication took place during this review.
