# Try Gramlot

Document ID: **GC-025**.

This repository contains the bounded native HTML/typed Source development core.
Local packages pass seven Chromium Host profiles; 0.1.0 is owner-accepted for GitHub archive delivery.

<a id="gc-025-005"></a>

## 005 · Choose the current foundation or experimental showcase

For current core behavior read [Writing pages](095-writing-pages.md) and [Classes/hosts](090-classes-and-hosts.md). Python Page authors native Source, while bindings/controllers/resolvers/components remain deferred. Local examples install package artifacts without sibling-source imports. For richer experimental behavior, download showcase.zip from [Gramlot Standalone](https://github.com/gramlot-org/gramlot-standalone/tree/main/examples/showcase), extract it and open showcase/index.html. Its PoC runtime includes binding, Show source and Inspector; offline RPC lacks its Python backend. Current core standalone instead runs a JS Page in a Worker through shared Host; the Node/npm exporter replaces the removed Python/JS compiler.

<a id="gc-025-010"></a>

## 010 · Choose a Host for a page

Python is the first authoring path. Current native HTML hosts are Uvicorn/ASGI, [FastAPI](https://github.com/gramlot-org/gramlot-fastapi/blob/main/docs/050-native-html.md), Flask and Kajenn; JS uses Node, Bun or Worker. Use each adapter's documented revision with locally built artifacts; package registries may differ. [Django](https://github.com/gramlot-org/gramlot-django) and [gramlot-poc](https://github.com/gramlot-org/gramlot-poc) remain experimental paths. PoC behavior does not extend the current core API.

## 015 · What to evaluate

For current core, inspect a Python Page, typed Source, marked remote block, live updates, freeze and cleanup. Evaluate bound fields, actions and Data changes against the experimental showcase's own documentation. Check server failures, required controls, adapter limits and tolerance for API changes. Read [quality](030-quality.md).

The core development manual now starts at [Classes and server adapters](090-classes-and-hosts.md). It describes the smaller native HTML foundation separately from the experimental showcase.

The native entry points are FastAPI `NativeHtmlApplication` / `mount_native_html`,
Flask `mount_native_html`, ASGI `NativeHtmlASGI`, Kajenn
`KajennNativeHtmlApplication`, and JS `gramlot-nodejs/native` / `gramlot-nodejs/bun`.
Use the [Hello World launch profiles](https://github.com/gramlot-org/gramlot-examples/tree/main/apps/hello-world)
with the prepared package artifacts. Legacy `GramlotApplication`, `mount_gramlot`
and PoC launch commands are outside the clean-core contract. Django, the Gramlot site and Rosetta were excluded from the original published
0.1.0 matrix; their PoC capabilities are not implied by that release.


Download the [0.1.0 archive set](https://github.com/gramlot-org/gramlot/releases/tag/v0.1.0).
Extract the complete bundle and follow its README: install all five Python wheels
together in a new environment, or all four npm archives together in a separate
consumer. Dependencies remain floating; internet access is required during setup.
The package registries are not the delivery source for this release.

Development after 0.1.0 groups these environments into **integration repos**:
`gramlot-fastapi`, `gramlot-flask`, `gramlot-kajenn`, `gramlot-minimal`,
`gramlot-nodejs` (Node.js and Bun), and `gramlot-django`. Minimal owns both
Python/ASGI/Uvicorn integration and browser/Worker standalone packaging. Kajenn
consumes minimal's generic ASGI adapter. The renamed development distributions
are `gramlot-minimal`, `gramlot-kajenn` and `@gramlot/minimal`; the published
0.1.0 archives and their original installation instructions remain unchanged.

The integration reorganization is local development work. GitHub repository
renames and publication are deferred pending reviewed PoC transfers and cleanup.

Local development now adds native Django integration through `NativeHtmlPages`
and ordinary Django URLconf mounting. Its native profile is separate from the
historical Page/ORM integration; no ORM migration is implied.
