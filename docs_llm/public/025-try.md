# Try Gramlot

Document ID: **GC-025**.

In a hurry? Start with [Try Gramlot: the quick route](018-quickstart.md).

Core: PyPI `gramlot`, npm `@gramlot/gramlot`. Adapters: `gramlot-py-server` (Python pages), `gramlot-js-server` (JavaScript pages); example pages: `gramlot-examples`.

<a id="gc-025-005"></a>

## 005 · Start with one learning environment

Start with Python and the Uvicorn adapter unless your application already uses another framework: basic Python, an editor, a browser; the adapter installs the core; no Node.js to serve Python pages; browser behavior runs in JavaScript through the page's `Logic` module. Open the gallery first (explanation, source, result; it does not save source edits; editing a field changes Data only), then create an editable project. Setup: [Python installation and commands](https://github.com/gramlot-org/gramlot-py-server/blob/main/docs/020-command.md), then section 015.

<a id="gc-025-010"></a>

## 010 · Open the gallery, then edit your own page

Extras `uvicorn` and `gallery`; follow the [Uvicorn guide](https://github.com/gramlot-org/gramlot-py-server/blob/main/docs/105-tutorial.md) and [gallery command](https://github.com/gramlot-org/gramlot-py-server/blob/main/docs/020-command.md#gp-020-010); the gallery prints its address; stop it before reusing the port. Hosted galleries without installation: [Python](https://gallery-py.gramlot.dev/), [JavaScript](https://gallery-js.gramlot.dev/).

`gramlot uvicorn new hello`, then the printed commands; edit `hello/pages/index.py` (Source) and `hello/pages/index.js` (Logic). `GRAMLOT_DEV=YES`: reload the page after a saved edit; `DEBUG` also the readable runtime; no hot reload; otherwise restart. The generated project uses named Logic and a strict CSP; inline gallery examples need the permissive profile ([CSP](090-classes-and-hosts.md#gc-090-035)).

| Alternative | Environment instructions |
| --- | --- |
| Existing Django, Flask, FastAPI or Kajenn site | [Python adapters](https://github.com/gramlot-org/gramlot-py-server); choose the framework's extra and guide. |
| JavaScript on Node/Bun | [JavaScript tutorial](https://github.com/gramlot-org/gramlot-js-server/blob/main/docs/010-tutorial.md); Page on the server, Logic in the browser. |
| JavaScript without an application server | [Standalone tutorial](https://github.com/gramlot-org/gramlot-js-server/blob/main/docs/135-serverless-tutorial.md); Page in a Worker, Logic in the window. Python pages cannot run there. |

## 015 · Learn by topic

Follow the gallery by subject. Start with familiar HTML, then compare a native
input with a Gramlot component before introducing reactive Data and server calls.
Each lesson has **Example**, **Explanation** and **Code** tabs: try one action,
observe its result, then change one declaration.

| Topic | What to learn | Next guide |
| --- | --- | --- |
| HTML and SVG | Nest elements, add styles and a shared `lbl`; distinguish `html_button` from a command component. | [Writing pages](095-writing-pages.md) |
| Fields and components | Select a collection; use richer typed controls, labels and validation. | [Components](105-components.md) |
| Data and bindings | Give each reusable block a relative `datapath`; distinguish `^` from `=` and UI defaults from loaded data. | [Data binding](097-data-binding.md) |
| Logic and events | Derive values with a formula; react with a controller or a named Logic method. | [Controllers](097-data-binding.md#gc-095-060) |
| RPC and remote content | Fetch values, lazy Bags or interface structure; keep these three results distinct. | [Server calls](098-server-calls.md), [remote content](099-remote-content.md) |
| Containers | Give regions, tabs, dialogs and floating windows a clear layout responsibility. | [Components](105-components.md) |
| Menus and toolbars | Reuse commands in hierarchical menus and toolbars. | [Menus and windows](350-menus-toolbars-and-windows.md) |
| Composition | Call a small helper repeatedly under different Data paths; preserve the same widgets when values change. | [Writing pages](095-writing-pages.md) |
| Appearance | Change density and palette without changing application behavior. | [Themes](096-themes-and-css.md) |

Use the [examples manual](https://gramlot-examples.readthedocs.io/en/latest/)
for the complete catalogue. The [visual tour](355-examples-and-visual-tour.md)
selects a few starting points; there is no need to read every lesson in order.

Prepared component collections work in the gallery. Host-specific resource
names in `js_requires` and authorization rules need the corresponding host
services; the gallery's `auth` example demonstrates refusal without an identity
provider. See [collections](340-components-and-collections-guide.md) for the
portable component package mechanism.

## 020 · One shared example suite, several integrations

Core owns framework docs, theme, logo; `gramlot-examples` owns pages, explanations, catalogue, gallery; integrations own setup, hosting and environment lessons and consume the suite. Commands: `gramlot <environment> gallery`; `npx gramlot node gallery`, `npx gramlot bun gallery`, `npx gramlot-serverless gallery <folder>`; the environment decides the page language; the Python page also uses the JavaScript Logic module beside it. Exact commands: [Updating an existing installation](018-quickstart.md). For changed lessons update gramlot-examples, core and adapter, then restart or rebuild the export; installations and exports do not refresh themselves; first-party dependencies unpinned; a checkout change reaches registries only with a release. [Shared reading path](https://github.com/gramlot-org/gramlot-examples/blob/main/src/gramlot_examples/pages/README.md) and [gallery package guide](https://github.com/gramlot-org/gramlot-examples/blob/main/docs/010-gallery.md) locate the files; a checkout is needed only to edit the suite.

<a id="gc-025-025"></a>

## 025 · Standalone export of the gallery

`npx gramlot-serverless gallery <folder>` writes the gallery as a folder; open its `index.html`, keep the folder together; no server or runtime installation; rebuild to update.
