# Try Gramlot

Document ID: **GC-025**.

> **Release status.** Describes **0.2.0 (HTML/SVG data binding)**: released 2026-09-30
> (PyPI `gramlot`, npm and JSR `@gramlot/gramlot`; current release in the README). Previous release:

This repository contains the Gramlot core: PyPI `gramlot`, npm and JSR `@gramlot/gramlot`.
Adapters: `gramlot-py-server` (Python pages), `gramlot-js-server` (JavaScript pages); examples: `gramlot-examples`.

## 005 · Choose the current foundation

For current core behavior read [Writing pages](095-writing-pages.md) and [Classes/hosts](090-classes-and-hosts.md). Python Page authors typed Source; resolvers and shared components are not in the core yet (*0.2.0:* bindings and controllers released in 0.2.0; try them in the gallery of [gramlot-examples](https://github.com/gramlot-org/gramlot-examples), `gramlot <environment> gallery` of [gramlot-py-server](https://github.com/gramlot-org/gramlot-py-server) or `npx gramlot node gallery` of [gramlot-js-server](https://github.com/gramlot-org/gramlot-js-server); described in [Writing pages](095-writing-pages.md)). Historical note: the `gramlot-minimal` repository, retired on 2026-09-28 and archived, published an offline showcase on the experimental [gramlot-poc](https://github.com/gramlot-org/gramlot-poc) runtime; its heirs are the `uvicorn` adapter of `gramlot-py-server` and `@gramlot/gramlot-serverless` in `gramlot-js-server`; the showcase is not maintained and is not an evaluation path. Current standalone integration is `@gramlot/gramlot-serverless`: it runs a JS Page in a Worker through the core shared Host and owns WorkerHost, WorkerTransport, startup and the Node/npm exporter. The old Python/JS compiler is removed.

## 010 · Choose a Host for a page

Python is the first authoring path. Python pages: [gramlot-py-server](https://github.com/gramlot-org/gramlot-py-server), `pip install "gramlot-py-server[<framework>]"` (`uvicorn`, `django`, `flask`, `fastapi`, `kajenn`), then `gramlot <framework> new <folder>`; it installs the core. JavaScript pages: [gramlot-js-server](https://github.com/gramlot-org/gramlot-js-server), `@gramlot/gramlot-js-server` (Node.js, Bun) or `@gramlot/gramlot-serverless` (no server); `npm create @gramlot page|site <folder>`. [gramlot-poc](https://github.com/gramlot-org/gramlot-poc) remains the experimental path. PoC behavior does not extend the current core API.

## 015 · What to evaluate

For current core, inspect a Python Page, typed Source, marked remote block, live updates, freeze and cleanup. Check server failures, required controls, adapter limits and tolerance for API changes. Read [quality](030-quality.md). *0.2.0:* the acceptance page (Python plus JS equivalent) is [`controllers/09_end_to_end`](https://github.com/gramlot-org/gramlot-examples/tree/main/src/gramlot_examples/pages/controllers) of gramlot-examples (route `c09`): a title bound to `.settings.caption`, an input, two radios, a checkbox, a computed result, a bound SVG and a button with a nested named `dataController`, with `dataSetter` after some controls. [`binding`](https://github.com/gramlot-org/gramlot-examples/tree/main/src/gramlot_examples/pages/binding) (11 pages) and [`controllers`](https://github.com/gramlot-org/gramlot-examples/tree/main/src/gramlot_examples/pages/controllers) (9 pages) cover each feature alone; evaluate against them.

The core development manual now starts at [Classes and server adapters](090-classes-and-hosts.md). It describes the smaller Gramlot core.

Adapter entry points, `gramlot-py-server`: `create_application`, `Application` (`.uvicorn`);
`Pages` (`.django`); `Pages`, `mount_pages` (`.flask`); `Pages`, `mount_pages`, `Application`
(`.fastapi`); `Application` (`.kajenn`). `gramlot-js-server`: `startServer` from
`@gramlot/gramlot-js-server/node` and `/bun`.
Use the quick starts of [gramlot-py-server](https://github.com/gramlot-org/gramlot-py-server#quick-start) and [gramlot-js-server](https://github.com/gramlot-org/gramlot-js-server#quick-start-a-server). Legacy `GramlotApplication`, `mount_gramlot`
and PoC launch commands are outside the clean-core contract. Django, the Gramlot site and Rosetta were excluded from the original published
0.1.0 matrix; their PoC capabilities are not implied by that release.


Download the [0.1.0 archive set](https://github.com/gramlot-org/gramlot/releases/tag/v0.1.0).
Extract the complete bundle and follow its README: install all five Python wheels
together in a new environment, or all four npm archives together in a separate
consumer. Dependencies remain floating; internet access is required during setup.
GitHub release assets are the delivery source for this nine-package archive set.
Separately, the JavaScript core was published on JSR as `@genro/gramlot` 0.1.0 on
2026-09-24. That registry publication is not the complete archive set above; its
matching version number does not establish identical contents. Follow the archive
README for this installation path. Later development changes are not implied by
either published 0.1.0 distribution.

After 0.1.0 these environments became **integration repos**, now two:
`gramlot-py-server` (PyPI; Uvicorn/ASGI, Django, Flask, FastAPI, Kajenn) and
`gramlot-js-server` (npm; Node.js and Bun, and `@gramlot/gramlot-serverless`).
Archived: `gramlot-uvicorn`, `gramlot-django`, `gramlot-fastapi`, `gramlot-flask`,
`gramlot-kajenn`, `gramlot-serverless`, and `gramlot-minimal` (retired 2026-09-28).
Django mounts through an ordinary URLconf, separate from the historical Page/ORM
integration. Published 0.1.0 archives and their instructions are unchanged.

## 020 · One shared example suite, several integrations

Gramlot is the upstream reference for framework documentation, logo and theme;
gramlot-examples holds the shared teaching suite: pages, READMEs, gallery page and catalogue. Read its manual first,
then the chosen integration's guide; clone that downstream repository for its
adapter, configuration and launch instructions. Read the Docs is the documentation
target, not a claim that all integration sites are already published.

Integrations consume gramlot-examples and Gramlot without maintaining local source copies; each owns its gallery command.
Python runs in the Uvicorn/ASGI, Django, Flask, FastAPI or Kajenn adapter of `gramlot-py-server`
(`gramlot <environment> gallery`); JavaScript runs in Node.js/Bun (`npx gramlot node|bun gallery`)
or the browser Worker of `@gramlot/gramlot-serverless` (`npx gramlot-serverless gallery <folder>`).
The integration selects the language.
Update the Gramlot dependency, then restart or regenerate the standalone export
to receive changes. Installed environments and exports do not refresh themselves.
Generated assets are outputs, not another source. First-party dependencies remain
unpinned; published 0.1.0 archives are immutable.

Sources in [gramlot-examples](https://github.com/gramlot-org/gramlot-examples) `src/gramlot_examples/pages/html_svg`, `binding` and `controllers`
(one file page per example: `NN_name.py`, `.js` with `Page` and `Logic`, `.md`, same-name `.css` where needed),
`src/gramlot_examples/gallery`, and in Gramlot `themes/gramlot-base`. Each integration
documents and tests its gallery command.

Development naming update: `gramlot-js-server` replaces `gramlot-nodejs` for both Node.js and Bun. Earlier 0.1.0 archive names remain historical.

## 025 · Standalone example download

The ready-to-use example ZIP was distributed through the releases of the
`gramlot-minimal` repository, retired on 2026-09-28 and archived.
A new example ZIP is not published. The core release's
`gramlot-native-0.1.0.zip` contains package artifacts, not this standalone demo.

`@gramlot/gramlot-serverless` writes the gallery of gramlot-examples as a folder
(`npx gramlot-serverless gallery <folder>`). Open its `index.html` in a browser;
keep the folder together. No application
server or runtime installation is needed. Rebuild or download a new export to
receive updates; an extracted directory does not update itself.
