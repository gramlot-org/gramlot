## 010 · Confirmed defects corrected

| Finding | Result and limits |
| --- | --- |
| `object.data` omitted from URL checks | JS and Python reject script URLs in literal, dialect and bound forms. Normal document URLs remain valid. This establishes a missing validation rule; it is not a claim that every browser executes the supplied object payload. |
| IDE uses secure-context-only `randomUUID` | Reuses the existing `randomId` helper based on `getRandomValues`. |
| Radio treats `==false` as truthy text | Uses the evaluated projection for expressions while preserving current Data reads for pointers, including freeze. |
| Typst Worker crash prevents retry | Rejects pending work, releases the failed Worker and allows the same preview owners to retry on a new shared Worker. Last-owner cleanup is retained. |
| Cancelling the restore picker leaves a pending Promise | Rejects with `AbortError`, without changing Data; an empty change event also settles. |
| Save shortcut publishes from locked editors | CodeMirror and Jodit consume the shortcut without publishing when readonly or disabled. Editable controls still publish. |
| HTTP close leaks rejection | Restores the documented best-effort cleanup behavior, including synchronous delivery failure. Server TTL owns undelivered cleanup. This intentional handling is not a user-facing error. |
| Runtime-owned `remote.update` calls leak rejection | Start, rebase, Data, delayed and periodic triggers use a handled path. Explicit `update` callers retain rejection. Async `_onRemote` failures are awaited and reported. Closed nodes do not alert. |
| Index selection fails before its existing catch | The selection boundary now handles validation/preparation failures and displays errors. Failed loads clean up and allow retry. A late failure from a closed tab cannot delete its reopened replacement. |
| Drag/drop errors only reach console | Shared notification covers start/target/drop/end failures. Intentional aborts and disposed pages do not alert. A pending drop whose target has been removed does not alert on late failure. |
| Commit failure mislabeled as validation notification | Commit and validation-callback failures have distinct visible titles. Async failures after control disposal do not create notifications. |

The notification is authored through Source and named Logic. It uses a manual
popover, does not focus or block the page, and remains until dismissed. Details
contain plain-text stack/cause information. Identical visible errors are
coalesced; distinct errors remain individually dismissible. It is internal
runtime presentation, not a new public proxy or application API.

## 020 · Incorrect, overstated or intentional behavior

- Filesystem endpoints are implemented by the Python integration in
  `gramlot_py_server/filesystem.py`; their absence from core is an ownership
  boundary, not proof that they do not exist. JS host parity is a separate gap.
- Markdown and Typst have executable tests; the claim of no coverage is false.
  HTML codec/preview coverage exists, but was not full Jodit editing coverage.
  This tranche adds the actual Jodit iframe save wiring test with an inert
  third-party engine, not a claim of full browser qualification.
- HTML and Markdown editor implementations overlap but are not identical
  line-for-line. CodeMirror has different engine semantics.
- Module import caches, style WeakSets and a shared Typst Worker are intentional
  resource ownership, not automatically shared application state. The Worker
  crash behavior was the actual defect and is corrected above.
- `postMessage('*')` for opaque-origin frames is part of the approved standalone
  contract. Window ownership/session/origin checks remain required. The review
  did not demonstrate a bypass; a correlation token is not a server credential.
- Storage exceptions in dropdown persistence and invalid draft parsing in the
  calendar have documented behavior. They should not all be turned into alerts.
- `formsubscribe_` is explicitly unsupported; its exclusion is not an accidental
  unreachable implementation to revive.
- Python/JS exception-class differences are not, on their own, a compatibility
  defect. Neither are technical uses of “native HTML”.
- Historical names in dated constitutional records must be retained as history;
  current naming guidance is authoritative. Parameter naming changes such as
  `order_by` remain separately scoped.
- Repeated `json.loads` calls and calls to shared native-attribute restoration do
  not by themselves prove duplicated algorithms. Internal subscription access is
  not equivalent to exposing a forbidden public proxy.
- The mobile device implementation differs between the audited baseline and the
  current integration candidate; claims about an absent DeviceHandler or
  DeviceResolver must be tied to the inspected revision.

## 055 — Editor content updates retain their engines (2026-10-25)

and CodeMirror, without recreation or state reset, with instance-identity regressions.
The owner also requires studying the embedded tool's API before writing its adapter.

and `group` remain a separate review; tree/grid content regeneration is not treated

API inspection and implementation:

- Jodit: `value` delegates to `getEditorValue`/`setEditorValue` and commits engine
  history. `history.undo`, `redo`, `canUndo`, `canRedo`, `snapshot.make` and
  `snapshot.restoreOnlySelection` provide the existing history/selection contracts.
  The adapter uses these APIs, never private history fields or a replacement Jodit.

- ProseMirror: a document transaction applies the changed fragment to the existing
  state/view, preserving plugins and mapped selection. `closeHistory` separates
  external edits from typing. Projection remains allowed while readonly; user
  history/edit commands remain blocked. No recreation of EditorView or fresh EditorState baseline.

## 060 — Jodit official sanitization and WebKit qualification (2026-10-26)

Owner authorized the dependency update and official sanitization while retaining
state, bindings and undo. Jodit is updated from 4.13.9 to 4.18.10 (npm current
version checked on 2026-10-26). References:
[official security guide](https://github.com/xdan/jodit/blob/main/docs/security.md),
[advisories](https://xdsoft.net/jodit/security/), and the installed upstream
`clean-html`, `paste`, `drag-and-drop`, `iframe` and selection implementations.

The editor uses `cleanHTML.sanitizer` with the existing DOMPurify dependency.
Its HTML profile rejects active embeds/form controls; only instance-owned history
comments and the codec's noneditable/data attributes are retained. FORCE_BODY
preserves a leading internal comment through DOMPurify's parser. Arbitrary
comments are removed; application comments are already protected placeholders.
No new sanitizer dependency or browser fallback is introduced. Form controls and
noscript are also codec placeholders, so filtering their visual projection does
not discard their original source on the next accepted edit.

The iframe now uses Jodit's default unsandboxed editing canvas for style isolation.
The script-disabled sandbox blocked WebKit's parent-installed editing callbacks.
CSP remains `default-src 'none'; script-src 'none'; style-src 'unsafe-inline';
img-src data:; form-action 'none'`. The separate Preview keeps its empty sandbox.
Original head/protected content is preserved by the codec, not treated as safe
HTML for application rendering. Server/storage/output sanitization remains the
host/application's responsibility; this GUI change creates no such service.

The ESM bundle now explicitly imports upstream paste and drag-and-drop plugins;
the minimal Jodit entry does not include them. HTML beautification is explicitly
disabled to avoid a dynamic external beautifier. No recreation/history reset was
introduced. The document codec remains necessary for source preservation, active
rich-edit rejection and correct head/body undo; it is not a complete sanitizer.

**Upstream limitation, not patched:** in 4.18.10, `Select.insertHTML` moves parsed
nodes to a DocumentFragment and `insertNode` emits `safeHTML(fragment)`.
`cleanHtml.onSafeHTML` invokes `sanitizer(sandBox.innerHTML)` and assigns the result
back to `sandBox.innerHTML`. A DocumentFragment has no native innerHTML; the
callback gets undefined and the assignment does not sanitize its children.
The subsequent built-in `safeHTML` still strips event attributes/unsafe links,
but does not replace the custom sanitizer's full policy. This is reproducible
with `editor.s.insertHTML` or an accepted HTML paste containing SVG/iframe/form
content. Do not claim the hook covers every insertion, patch dependency sources,
or add a second ingress pipeline as a consumer workaround. The existing codec
rejects active content synchronously; CSP prevents attempted execution during
upstream insertion. Chromium reports expected CSP blocks for adversarial probes.
A fix belongs in Jodit; no upstream issue was sent or fix claimed in this task.

Verification: 63 targeted Node tests pass, covering editor identity/history,
codec, save shortcuts, IDE Revert/ownership, binding cleanup and declarations.
The core-only real-engine fixture passes Chromium and WebKit: typing reaches
Data, external projection is silent, compatible selection survives, previous
history/head/protected context remains available, readonly and deferred writes
work, safe paste/drop is undoable, active paste/drop does not modify Data or
execute payloads, history remains usable after rejection, and disposal releases
engines. The runtime build passes. This closes the WebKit typing limitation in
§055, not every conceivable Jodit security issue or device qualification.
No package publication, deployment, or first-party dependency-source changes.
