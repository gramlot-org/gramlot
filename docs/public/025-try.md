# Try Gramlot

Document ID: **GC-025**.

> **Release status.** This page describes Gramlot **0.2.0 (HTML/SVG data
> binding)**, released on 2026-09-30 and is published on PyPI (`gramlot`)
> and on npm and JSR (`@gramlot/gramlot`); the README states the current release. The previous release is **0.1.2**.
> Text without a *0.2.0* mark describes behavior that comes from 0.1.2.

This repository contains the Gramlot core, published on PyPI (`gramlot`) and on
npm and JSR (`@gramlot/gramlot`). The adapters are in `gramlot-py-server` (Python
pages) and `gramlot-js-server` (JavaScript pages); the example pages are in
`gramlot-examples`.

<a id="gc-025-005"></a>

## 005 · Choose the current foundation

For the current foundation, read [Writing pages](095-writing-pages.md) and
[Classes and server adapters](090-classes-and-hosts.md). A Python `Page` declares
typed Source; its Host supplies bootstrap and main. Resolvers and shared components are not part of the core yet.
*0.2.0:* Data bindings and controllers are released in 0.2.0.
Try them in the gallery of [gramlot-examples](https://github.com/gramlot-org/gramlot-examples): `gramlot <environment> gallery` of [gramlot-py-server](https://github.com/gramlot-org/gramlot-py-server) or `npx gramlot node gallery` of [gramlot-js-server](https://github.com/gramlot-org/gramlot-js-server);
[Writing pages](095-writing-pages.md) describes them.

Historical note: the `gramlot-minimal` repository, retired on 2026-09-28 and
archived, published an offline showcase built on the experimental runtime of
[gramlot-poc](https://github.com/gramlot-org/gramlot-poc). Its heirs are the
`uvicorn` adapter of `gramlot-py-server` and `@gramlot/gramlot-serverless` in
`gramlot-js-server`. The showcase is not maintained and is not an evaluation path.

The current standalone integration, `@gramlot/gramlot-serverless`, runs a JS Page in a
Worker using the core's shared Host contract. It owns WorkerHost, WorkerTransport,
startup and the Node/npm exporter that packages JS Pages. The old build-time
Python/JS compiler has been removed.
See [the Worker host](090-classes-and-hosts.md) for current scope.

## 010 · Choose a Host for a page

Python is the first authoring path. Install the adapter of your framework from
PyPI; it installs the core. JavaScript Pages use the Node.js/Bun adapter or the
Worker standalone host, from npm.

| Evaluation path | Start here |
| --- | --- |
| Serve Python pages | [gramlot-py-server](https://github.com/gramlot-org/gramlot-py-server): `pip install "gramlot-py-server[<framework>]"` with `uvicorn`, `django`, `flask`, `fastapi` or `kajenn`, then `gramlot <framework> new <folder>` |
| Serve JavaScript pages | [gramlot-js-server](https://github.com/gramlot-org/gramlot-js-server): `@gramlot/gramlot-js-server` (Node.js, Bun) or `@gramlot/gramlot-serverless` (no server); `npm create @gramlot page <folder>` (or `site`) |
| Explore richer experimental features | [Gramlot PoC](https://github.com/gramlot-org/gramlot-poc) |

Each integration owns its installation instructions and supported scope. The
current core API is described by this repository's development guides;
PoC examples do not extend that API.

## 015 · What to evaluate

For the current foundation, start with a small Python Page, inspect its typed
Source and test live updates, freeze/unfreeze and cleanup.
Check request failures as well as successful responses for a server-backed
application.

Before choosing Gramlot for an application, assess the controls you need, the
chosen adapter's limitations, and how much API change your project can tolerate.
Read [Tests and coverage](030-quality.md) alongside the examples.

*0.2.0:* the end-to-end page, in Python with a JavaScript equivalent, is
[`controllers/08_end_to_end`](https://github.com/gramlot-org/gramlot-examples/tree/main/src/gramlot_examples/pages/controllers) of gramlot-examples (route `c08` in the gallery). It
combines a title bound to `.settings.caption`, an input, two radios and a
checkbox, a computed result, an SVG with bound colour and size, and a button with
a nested named `dataController`. Its `dataSetter` declarations follow some
controls. The families [`binding`](https://github.com/gramlot-org/gramlot-examples/tree/main/src/gramlot_examples/pages/binding) (eleven pages) and
[`controllers`](https://github.com/gramlot-org/gramlot-examples/tree/main/src/gramlot_examples/pages/controllers) (eight pages) cover each 0.2.0 feature on its own; use them
as the evaluation reference.

The core development manual now starts at [Classes and server adapters](090-classes-and-hosts.md). It describes the smaller Gramlot core.

The adapter entry points of `gramlot-py-server` are `create_application` and
`Application` (`gramlot_py_server.uvicorn`), `Pages` (`gramlot_py_server.django`),
`Pages` and `mount_pages` (`gramlot_py_server.flask`), `Pages`, `mount_pages` and
`Application` (`gramlot_py_server.fastapi`) and `Application`
(`gramlot_py_server.kajenn`). The entry points of `gramlot-js-server` are
`startServer` from `@gramlot/gramlot-js-server/node` and `/bun`.
Use the quick starts of [gramlot-py-server](https://github.com/gramlot-org/gramlot-py-server#quick-start) and [gramlot-js-server](https://github.com/gramlot-org/gramlot-js-server#quick-start-a-server). Legacy `GramlotApplication`, `mount_gramlot`
and PoC launch commands are outside the clean-core contract. Django, the Gramlot site and Rosetta were excluded from the original published
0.1.0 matrix; their PoC capabilities are not implied by that release.


Download the [0.1.0 archive set](https://github.com/gramlot-org/gramlot/releases/tag/v0.1.0).
Extract the complete bundle and follow its README: install all five Python wheels
together in a new environment, or all four npm archives together in a separate
consumer. Dependencies remain floating; internet access is required during setup.
GitHub release assets are the delivery source for this nine-package archive set.
Separately, the JavaScript core was published on JSR as `@genro/gramlot` 0.1.0 on
2026-09-24. That registry publication is not the complete archive set above; its
matching version number does not establish identical contents. Follow the archive
README for this installation path. Later development changes are not implied by
either published 0.1.0 distribution.

After 0.1.0 these environments became **integration repos**, now two:
`gramlot-py-server` (PyPI; adapters for Uvicorn/ASGI, Django, Flask, FastAPI and
Kajenn) and `gramlot-js-server` (npm; Node.js and Bun, and the browser/Worker
standalone package `@gramlot/gramlot-serverless`). The intermediate repositories
`gramlot-uvicorn`, `gramlot-django`, `gramlot-fastapi`, `gramlot-flask`,
`gramlot-kajenn` and `gramlot-serverless`, and `gramlot-minimal`, retired on
2026-09-28, are archived. The Django adapter mounts the pages through an ordinary
URLconf; it is separate from the historical Page/ORM integration. The published
0.1.0 archives and their original installation instructions remain unchanged.

## 020 · One shared example suite, several integrations

Gramlot is the primary reference for framework concepts, APIs and the shared
teaching examples. Start with its documentation on Read the Docs and its source
repository. Then choose an integration, read its environment-specific guide and
clone that integration repository to configure and run the examples in that host.
Read the Docs is the documentation delivery target; this policy does not claim
that every integration site is already connected or published.

The integration repositories are downstream consumers of Gramlot and of
gramlot-examples. gramlot-examples owns the example pages, their READMEs, the
gallery page and its catalogue; Gramlot owns the logo and the shared theme.
Integrations own adapters, environment configuration, launch commands, the gallery
command and hosting instructions. They must consume the shared material from the
gramlot-examples and Gramlot dependencies rather than maintain copied teaching suites. Generated installation or export assets are
reproducible outputs, not independently maintained sources.

Python examples run inside the Uvicorn/ASGI, Django, Flask, FastAPI or Kajenn
adapter of `gramlot-py-server` (`gramlot <environment> gallery`). JavaScript
examples run inside Node.js or Bun (`npx gramlot node gallery`, `npx gramlot bun
gallery`) or the browser Worker standalone profile of `@gramlot/gramlot-serverless`
(`npx gramlot-serverless gallery <folder>`). The integration selects the execution
language; the gallery does not ask users to switch between Python and JavaScript.

To receive changed examples, update the Gramlot dependency following the chosen
integration's setup instructions, then restart the host or rebuild the standalone
export. An existing installation or exported folder does not update itself when
upstream changes. First-party dependencies remain unpinned; the published 0.1.0
archives remain immutable.

This is the agreed distribution model. The teaching sources live in
[gramlot-examples](https://github.com/gramlot-org/gramlot-examples) under `src/gramlot_examples/pages/html_svg`, `binding` and
`controllers`, one file page per example (`01_hello_world.py`, `01_hello_world.js`
with `Page` and `Logic`, `01_hello_world.md` and, where the example has one, the
same-name stylesheet), the gallery page under `src/gramlot_examples/gallery`, and
the theme in Gramlot under `themes/gramlot-base`. Each integration repository
documents and tests its gallery command.

Development naming update: `gramlot-js-server` replaces `gramlot-nodejs` for both Node.js and Bun. Earlier 0.1.0 archive names remain historical.

## 025 · Standalone example download

The ready-to-use example ZIP was distributed through the releases of the
`gramlot-minimal` repository, retired on 2026-09-28 and archived.
A new example ZIP is not published. The core release's
`gramlot-native-0.1.0.zip` contains package artifacts, not this standalone demo.

The standalone integration `@gramlot/gramlot-serverless` writes the gallery of gramlot-examples as
a folder (`npx gramlot-serverless gallery <folder>`). Open its `index.html` in a
browser; keep the folder together. No application
server or runtime installation is needed. Rebuild or download a new export to
receive updates; an extracted directory does not update itself.
