# Try Gramlot

Document ID: **GC-025**.

> **Release status.** This page describes Gramlot **0.2.0 (HTML/SVG data
> binding)**. The code is implemented on the development branch and is in
> qualification; it is not released. The latest published release is **0.1.2**.
> Text without a *0.2.0* mark describes behavior that comes from 0.1.2.

This repository contains the bounded native HTML development foundation. Local
package installations have passed Uvicorn, FastAPI, Kajenn, Flask, Node, Bun and
Worker checks in Chromium. The owner accepted 0.1.0 on 2026-09-24 for GitHub archive delivery.

## 005 · Choose the current foundation

For the current foundation, read [Writing pages](095-writing-pages.md) and
[Classes and server adapters](090-classes-and-hosts.md). A Python `Page` declares
native Source; its Host supplies bootstrap, main and explicitly marked remote
Source. Data bindings, controllers, resolvers and shared components are deferred.
*0.2.0:* Data bindings and controllers are implemented for 0.2.0, not yet released.
Try them from a development checkout with the local runner (`examples/00-runner`);
[Writing pages](095-writing-pages.md) describes them.
The verified packages were built from these development checkouts and installed
as artifacts; no sibling-source import is needed by the example page.

Historical note: until 2026-09-26 the `gramlot-minimal` repository published an
offline showcase built on the experimental runtime of
[gramlot-poc](https://github.com/gramlot-org/gramlot-poc). The repository is retired
and archived; its heirs are `gramlot-uvicorn` and `gramlot-serverless`. The
showcase is not maintained and is not an evaluation path.

The current standalone integration, `gramlot-serverless`, runs a JS Page in a
Worker using the core's shared Host contract. It owns WorkerHost, WorkerTransport,
startup and the Node/npm exporter that packages JS Pages. The old build-time
Python/JS compiler has been removed.
See [the Worker host](090-classes-and-hosts.md) for current scope.

## 010 · Choose a Host for a page

Python is the first authoring path. Use a current adapter's documented setup and
revision with a locally built Gramlot wheel; do not assume a package registry
already carries this development state. JavaScript Pages use the Node/Bun adapter
or the Worker standalone host. The local seven-profile check installed package
artifacts in new environments and exercised the same bounded behavior.

| Evaluation path | Start here |
| --- | --- |
| Serve current native HTML Python pages | Uvicorn/ASGI, [FastAPI](https://github.com/gramlot-org/gramlot-fastapi/blob/main/docs/050-native-html.md), Flask or Kajenn adapter |
| Serve current native HTML JavaScript pages | Node, Bun or the Worker standalone host |
| Explore richer experimental features, including Django integration | [Gramlot PoC](https://github.com/gramlot-org/gramlot-poc) and [Gramlot Django](https://github.com/gramlot-org/gramlot-django) |

Each integration owns its installation instructions and supported scope. The
current native HTML API is described by this repository's development guides;
PoC examples do not extend that API.

## 015 · What to evaluate

For the current foundation, start with a small Python Page, inspect its typed
Source and test a marked remote block, live updates, freeze/unfreeze and cleanup.
Check request failures as well as successful responses for a server-backed
application.

Before choosing Gramlot for an application, assess the controls you need, the
chosen adapter's limitations, and how much API change your project can tolerate.
Read [Tests and coverage](030-quality.md) alongside the examples.

*0.2.0:* the acceptance page, in Python with a JavaScript equivalent, is
`examples/controllers/09_end_to_end` (route `c09` in the local runner). It
combines a title bound to `.settings.caption`, an input, two radios and a
checkbox, a computed result, an SVG with bound colour and size, and a button with
a nested named `dataController`. Its `dataSetter` declarations follow some
controls. The families `examples/binding/` (eleven pages) and
`examples/controllers/` (nine pages) cover each 0.2.0 feature on its own; use them
as the evaluation reference.

The core development manual now starts at [Classes and server adapters](090-classes-and-hosts.md). It describes the smaller native HTML foundation.

The native entry points are FastAPI `NativeHtmlApplication` / `mount_native_html`,
Flask `mount_native_html`, ASGI `NativeHtmlASGI`, Kajenn
`KajennNativeHtmlApplication`, and JS `gramlot-js-server/native` / `gramlot-js-server/bun`.
Use the [Hello World launch profiles](https://github.com/gramlot-org/gramlot-examples/tree/main/apps/hello-world)
with the prepared package artifacts. Legacy `GramlotApplication`, `mount_gramlot`
and PoC launch commands are outside the clean-core contract. Django, the Gramlot site and Rosetta were excluded from the original published
0.1.0 matrix; their PoC capabilities are not implied by that release.


Download the [0.1.0 archive set](https://github.com/gramlot-org/gramlot/releases/tag/v0.1.0).
Extract the complete bundle and follow its README: install all five Python wheels
together in a new environment, or all four npm archives together in a separate
consumer. Dependencies remain floating; internet access is required during setup.
GitHub release assets are the delivery source for this nine-package archive set.
Separately, the JavaScript core was published on JSR as `@genro/gramlot` 0.1.0 on
2026-09-24. That registry publication is not the complete archive set above; its
matching version number does not establish identical contents. Follow the archive
README for this installation path. Later development changes are not implied by
either published 0.1.0 distribution.

Development after 0.1.0 groups these environments into **integration repos**:
`gramlot-fastapi`, `gramlot-flask`, `gramlot-kajenn`, `gramlot-uvicorn`,
`gramlot-serverless`, `gramlot-js-server` (Node.js and Bun), and
`gramlot-django`. `gramlot-uvicorn` owns Python/ASGI/Uvicorn integration and
`gramlot-serverless` owns browser/Worker standalone packaging; both replace
`gramlot-minimal`, which was retired on 2026-09-26. `gramlot-kajenn` depends only
on Kajenn besides the core (constitution amendment 11.48 item 5). The Kajenn adapter
is not migrated yet and is deferred to after 0.2.0. The published 0.1.0 archives and their
original installation instructions remain unchanged.

`gramlot-uvicorn`, `gramlot-serverless` and `gramlot-js-server` exist locally and
on GitHub. `gramlot-kajenn` was renamed from `gramlot-genro-asgi` on 2026-09-26, on GitHub
and locally.
Further package publication remains separate work.

Local development now adds native Django integration through `NativeHtmlPages`
and ordinary Django URLconf mounting. Its native profile is separate from the
historical Page/ORM integration; no ORM migration is implied.

## 020 · One shared example suite, several integrations

Gramlot is the primary reference for framework concepts, APIs and the shared
teaching examples. Start with its documentation on Read the Docs and its source
repository. Then choose an integration, read its environment-specific guide and
clone that integration repository to configure and run the examples in that host.
Read the Docs is the documentation delivery target; this policy does not claim
that every integration site is already connected or published.

The integration repositories are downstream consumers of Gramlot. Gramlot owns
the example pages, their READMEs, the runner, logo and shared theme. Integrations
own adapters, environment configuration, launch commands and hosting instructions.
They must consume the shared material from the Gramlot dependency rather than
maintain copied teaching suites. Generated installation or export assets are
reproducible outputs, not independently maintained sources.

Python examples run inside Flask, FastAPI, Django, Kajenn or the Uvicorn profile of
`gramlot-uvicorn`. JavaScript examples run inside Node.js/Bun or the browser Worker
standalone profile of `gramlot-serverless`. The integration selects the execution language; the shared
runner does not ask users to switch between Python and JavaScript.

To receive changed examples, update the Gramlot dependency following the chosen
integration's setup instructions, then restart the host or rebuild the standalone
export. An existing installation or exported folder does not update itself when
upstream changes. First-party dependencies remain unpinned; the published 0.1.0
archives remain immutable.

This is the agreed distribution model. The teaching sources already live in
Gramlot under `examples/html_svg`, `examples/binding` and `examples/controllers`,
one file page per example (`01_hello_world.py`,
`01_hello_world.js`, `01_hello_world.md` and, where the example has one, the
same-name stylesheet and logic companion `01_name_aux.js`), the runner under
`examples/00-runner`, and the theme under `themes/gramlot-base`. Uniform dependency packaging and example launch
commands across all six integrations still need implementation and verification.
Existing Hello World smoke launchers and historical demos do not establish that
this shared teaching-suite workflow is already available in every integration.

Development naming update: `gramlot-js-server` replaces `gramlot-nodejs` for both Node.js and Bun. Earlier 0.1.0 archive names remain historical.

## 025 · Standalone example download

The ready-to-use example ZIP was distributed through the releases of the retired
`gramlot-minimal` repository (archived on 2026-09-26).
The new thirteen-example runner ZIP is not yet published. The core release's
`gramlot-native-0.1.0.zip` contains package artifacts, not this standalone demo.

The standalone integration `gramlot-serverless` generates the archive from the shared Gramlot examples, runner and theme,
and records the Gramlot version used. Once available, extract the entire archive
and open its `index.html` in a browser; keep the folder together. No application
server or runtime installation is needed. Rebuild or download a new export to
receive updates; an extracted directory does not update itself.
