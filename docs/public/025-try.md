# Try Gramlot

Document ID: **GC-025**.

In a hurry? Start with [Try Gramlot: the quick route](018-quickstart.md).

> **Scope.** This is the maintained authoring guide. The repository README states
> the current release. Dated release notes below describe when behavior entered;
> they are not a list of current exclusions. Development-only differences are marked.

This repository contains the Gramlot core, published on PyPI (`gramlot`) and on
npm and JSR (`@gramlot/gramlot`). The adapters are in `gramlot-py-server` (Python
pages) and `gramlot-js-server` (JavaScript pages); the example pages are in
`gramlot-examples`.

<a id="gc-025-005"></a>

## 005 · Start with one learning environment

Start with Python and the Uvicorn adapter unless your application already uses
another framework. You need basic Python, a text editor and a browser. The
adapter installs the core; Node.js is not needed to serve Python pages. Browser
behavior still runs in JavaScript, through the page's `Logic` module.

First open the gallery to compare explanation, source and result. Then create an
editable project. The gallery displays source but does not save edits to it;
changing a field changes page Data, not the Python/JavaScript file.

Use the [Python installation and commands](https://github.com/gramlot-org/gramlot-py-server/blob/main/docs/020-command.md)
for the environment setup, then return to the route in section 015.

<a id="gc-025-010"></a>

## 010 · Open the gallery, then edit your own page

The Python package needs the `uvicorn` and `gallery` extras for this route. In a
Python virtual environment, follow the [Uvicorn guide](https://github.com/gramlot-org/gramlot-py-server/blob/main/docs/105-tutorial.md)
and [gallery command](https://github.com/gramlot-org/gramlot-py-server/blob/main/docs/020-command.md#gp-020-010).
The gallery prints its address. Stop it before reusing its port.

Create a separate empty project with `gramlot uvicorn new hello`, then follow the
printed install/start commands. Edit `hello/pages/index.py` for Source and
`hello/pages/index.js` for browser Logic. With `GRAMLOT_DEV=YES`, reopen/reload the
page after a saved edit; `DEBUG` also selects the readable runtime. This is not
automatic hot reload. Without development reload, restart the server as needed.

The generated project uses named Logic and a strict CSP. Inline gallery examples
need the documented permissive profile; copying inline code into the strict
project does not make it named Logic. See [CSP](090-classes-and-hosts.md).

| Alternative | Environment instructions |
| --- | --- |
| Existing Django, Flask, FastAPI or Kajenn site | [Python adapters](https://github.com/gramlot-org/gramlot-py-server); choose the framework's extra and guide. |
| JavaScript on Node/Bun | [JavaScript tutorial](https://github.com/gramlot-org/gramlot-js-server/blob/main/docs/010-tutorial.md); Page on the server, Logic in the browser. |
| JavaScript without an application server | [Standalone tutorial](https://github.com/gramlot-org/gramlot-js-server/blob/main/docs/135-serverless-tutorial.md); Page in a Worker, Logic in the window. Python pages cannot run there. |

## 015 · Learn through the release sequence

The teaching sequence follows the releases: first build with the capabilities of
an earlier stage, then revisit the same problem when a later release provides a
simpler declaration. The topic reference and prerequisites support that sequence;
they do not replace it. The version labels below identify **core milestones**,
not the independently numbered examples or adapter packages.

**0.1.x: HTML/SVG and live Source.** Build structure and understand Source before reactive Data. Later annotations in these sections explicitly identify additions.

Read and try: Writing pages §§005–035; e01, e03, e06, e08, e12.

**0.2.0: bindings and controllers.** Revisit e06 → b09, e08 → b10 and e12 → b11: Data declarations connect values to the interface. Then combine the mechanisms in c08's local story.

Read and try: §§040–090; b01–b11, c01–c08, c15 and c16's first section.

**0.2.3: sandboxed HTML previews from Data.** Revisit the bound text in c16 with a separate iframe preview. Observe the default sandbox and keep its limits distinct from ordinary text projection.

Read and try: Writing pages §065; c16's later section.

**0.2.5: page Logic module and data exchange.** Revisit page behavior with Logic beside Page. c17 revisits a form record with local save/restore and export. Its public path became gramlot.utl.inout in 0.2.10.

Read and try: §§060 and 095; c03 and c17.

**0.2.9–0.2.12: runtime responsibilities and server names.** Recognize the current src/rpc/dom/utl proxies and GramlotServer names in maintained code; these are reference updates, not a reason to invent another exercise.

Read and try: Classes and server adapters §§015–022.

**0.2.14: endpoint calls.** Extend local interaction with dataRpc: a Page method returns a value into Data. Learn visible errors as well as success.

Read and try: §100; c09–c11, then return to c08's separately labelled 0.2.14 quote/result/error section.

**0.2.15: Source authorization.** Explain server-side removal of refused Source subtrees. The common gallery does not demonstrate authenticated allow/deny.

Read and try: §100 authorization note; identity-aware adapter guide.

**0.2.16: remote Source and lazy Data.** Revisit server interaction: remote mounts Source; dataRemote loads a value when read. Compare responsibilities and triggers with dataRpc.

Read and try: §105; c12–c14.

The existing pages use maintained APIs; they are **not executable snapshots of old
packages**. Do not downgrade dependencies to follow the chronology. Release-scoped
before/after comparisons must label the earlier form and link the earlier lesson,
show what new feature replaces which code, and preserve the intended result.
Repeating an example for that comparison is intentional. The fuller comparisons
are being prepared; the route does not claim they have all been delivered.

Within each release stage, read the lesson's prerequisites and predict the result
before trying it. For example, in c01 changing VAT alone does not recalculate gross;
changing quantity afterwards uses the new VAT. c08 preserves its **local**
binding/lifecycle stage and appends a separate 0.2.14 trial after c09/c11: a button
requests a server quote, displays success/error and retains the last successful
result on failure. Its exercise changes only the host calculation, making the
local preview/server snapshot distinction visible. The first pass sends no quote
request; the later stage does not reorder the release narrative.

The common catalogue contains e01–e13, b01–b11 and the controller lessons listed in the [examples README](https://github.com/gramlot-org/gramlot-examples#pages). c16 labels the intervening 0.2.3 sandbox step separately. Some advanced
exercises are still missing; see [coverage limits](095-writing-pages.md) and
[Tests and coverage](030-quality.md). An installed older catalogue may show fewer
pages. Follow the adapter's setup/update guide rather than treating missing pages
as a runtime feature failure.

### Historical archive instructions

> **Historical record (2026-09-24–2026-10-02):** the following installation notes
> describe the original archive delivery, not the learning setup above.

Download the [0.1.0 archive set](https://github.com/gramlot-org/gramlot/releases/tag/v0.1.0).
Extract the complete bundle and follow its README: install all five Python wheels
together in a new environment, or all four npm archives together in a separate
consumer. Dependencies remain floating; internet access is required during setup.
GitHub release assets are the delivery source for this nine-package archive set.
Separately, the JavaScript core was published on JSR as `@genro/gramlot` 0.1.0 on
2026-09-24. That registry publication is not the complete archive set above; its
matching version number does not establish identical contents. Follow the archive
README for this installation path. Later development changes are not implied by
either published 0.1.0 distribution.

After 0.1.0 these environments became **integration repos**, now two:
`gramlot-py-server` (PyPI; adapters for Uvicorn/ASGI, Django, Flask, FastAPI and
Kajenn) and `gramlot-js-server` (npm; Node.js and Bun, and the browser/Worker
standalone package `@gramlot/gramlot-serverless`). The intermediate repositories
`gramlot-uvicorn`, `gramlot-django`, `gramlot-fastapi`, `gramlot-flask`,
`gramlot-kajenn` and `gramlot-serverless`, and `gramlot-minimal`, retired on
2026-09-28, are archived. The Django adapter mounts the pages through an ordinary
URLconf; it is separate from the historical Page/ORM integration. The published
0.1.0 archives and their original installation instructions remain unchanged.

## 020 · One shared example suite, several integrations

The core owns framework documentation, theme and logo. `gramlot-examples` owns
the pages, their explanations, catalogue and gallery. Integrations own setup,
hosting and their environment-specific lessons; they consume the common suite
instead of maintaining copies.

Python uses `gramlot <environment> gallery`; JavaScript uses `npx gramlot node
gallery`, `npx gramlot bun gallery` or `npx gramlot-serverless gallery <folder>`.
The environment determines the page language. Source is displayed alongside the
explanation; the Python page also uses the JavaScript Logic module beside it.

For exact commands, use [Updating an existing installation](018-quickstart.md).

To receive changed lessons, update **gramlot-examples as well as the core and
adapter** following the owning setup guide, then restart or rebuild the export.
Installed environments and exported folders do not refresh themselves. First-party
dependencies remain unpinned. A local development correction is not automatically
available in registry packages or the public site.

The [shared reading path](https://github.com/gramlot-org/gramlot-examples/blob/main/src/gramlot_examples/pages/README.md)
and [gallery package guide](https://github.com/gramlot-org/gramlot-examples/blob/main/docs/010-gallery.md)
locate the files and explain the presentation. A repository checkout is useful for
editing the suite; it is not required just to run a packaged gallery.

## 025 · Standalone example download

> **Historical record (through 2026-09-28):** the retired download below is not the current gallery setup.

The ready-to-use example ZIP was distributed through the releases of the
`gramlot-minimal` repository, retired on 2026-09-28 and archived.
A new example ZIP is not published. The core release's
`gramlot-native-0.1.0.zip` contains package artifacts, not this standalone demo.

The standalone integration `@gramlot/gramlot-serverless` writes the gallery of gramlot-examples as
a folder (`npx gramlot-serverless gallery <folder>`). Open its `index.html` in a
browser; keep the folder together. No application
server or runtime installation is needed. Rebuild or download a new export to
receive updates; an extracted directory does not update itself.
