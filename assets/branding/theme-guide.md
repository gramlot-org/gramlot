# Gramlot — visual identity and application theme

Version 0.3 · 2026-10-02. Identity and supporting palette approved on 2026-09-18; rich kit completion authorized on 2026-10-02. New vector artwork and layouts await owner visual acceptance.

## 1. Approved identity

Blue `#456BC4`, yellow `#FFC400`; asymmetric curved symbol and detached disc.
The name is **gramlot**, all lowercase, in **Arial Rounded MT Bold**, centered
below the symbol. Current tracking is −0.025 em. Preserve orientation and proportions.
The SVG lettering is outlined, so viewing it does not require a locally installed font.
Font files are not distributed. A UI font is a separate choice.

## 2. Asset files and production formats

Start with the [visual catalogue](index.html), [kit inventory](README.md) or
complete ZIP (generated by `source/build_assets.py`, not committed). The single path-only vector master is
`source/gramlot-master.svg`; lettering paths are preserved from the original.
The symbol was reconstructed from the selected raster reference with smooth
Bezier contours and approved solid colors. Light/dark exports share one geometry.

- `svg/`: transparent stacked logo, horizontal logo, symbol and standalone wordmark;
  primary, inverse, blue, ink, black and white variants.
- `png/`: transparent exports with pixel width in the name, from 64 to 2048 px.
- `icons/`: SVG/ICO/PNG favicons, device and maskable icons; see its integration guide.
- `palette/`: CSS, JSON, GIMP GPL and SVG color resources.
- `social/`: five light/dark compositions in SVG and PNG.
- `backgrounds/`: wallpapers and presentation backgrounds.
- `print/gramlot-identity-guide.pdf`: four-page RGB guide with vector logo paths.
- Original raster/hybrid files of 2026-09-18: in git history, [commit `234c6d8`](https://github.com/gramlot-org/gramlot/tree/234c6d8/assets/branding).

The stable `gramlot-logo.svg`/`gramlot-logo-dark.svg` and
`gramlot-mark.png`/`gramlot-mark-dark.png` entry points retain their white/navy
backgrounds and original composition, now exported from the vector master.
Transparent variants live in `svg/` and `png/`. Root background-specific assets
are not intended for arbitrary surfaces.

Use the symbol at 64 px or larger initially, and the full logo at 160 px or larger;
these are working recommendations, not certified minimum sizes. Browser icon
exports also include 16/24/32/48 px; inspect thin tips on the actual target.
Leave at least one disc diameter around visible artwork. Do not stretch, rotate,
add shadows or recolor the logo to communicate state. One-color utility exports
support monochrome reproduction.

The new vector reconstruction and layouts remain subject to owner visual review.
RGB artwork does not establish a printer-specific CMYK or spot-color contract.

## 3. Approved supporting palette

Keep blue and yellow as the identity pair. Add midnight navy for navigation,
a slightly warm near-white for pages and slate for secondary text. Pale blue is a
selection surface. Green, amber and muted red are semantic colors, not extra logo colors.

Use white text on blue actions, navy text on yellow, and light text on navy.
Yellow is an accent, never small text on white. Do not reuse the light-mode action
color for small link text on dark surfaces; use `#EDF2FA` with an underline there.
Pair status colors with explicit labels and icons. Decorative borders are not
sufficient as essential control boundaries; use the control token and verify its
contrast against the actual surface. See `contrast-check.json` for calculated
opaque text pairs; this is not a rendered accessibility audit.

## 4. Typography and layout

Use system sans-serif for UI text, monospace for code. Reserve Arial Rounded for
the brand name. Start with 16/24 px body, 14/21 px controls, 12/18 px metadata,
20/28 px section titles and 28/36 px page titles. Avoid dense all-caps labels.
Use spacing 4/8/12/16/24/32/48 px, radii 6–8 px, and clear keyboard focus.
Keep forms, trees and tables calm; do not repeat yellow decoration in every panel.
Use labels for loading, empty, unauthorized and failed states. Respect reduced motion.

## 5. Scope and coordination

These tokens are an owner-approved design specification, not installed Gramlot runtime defaults.
They coordinate with Kajenn through restrained surfaces and spacing while retaining
Gramlot's independent blue/yellow identity. No server or database dependency is implied.
Classic Read the Docs styling remains required by the constitution; this guide does
not replace its default typography or blue/dark/light appearance. Any future application
showcase must use Gramlot's own authoring and component mechanisms.

## 6. Production review and handoff

The owner authorized this kit on 2026-10-02: “puoi provvedere e creare una bella
cartella con tutto il necessario per un immagine grafica ? bella ricca”. The scope
completes the previous audit's missing vector, transparent, monochrome and favicon
assets while preserving the selected identity. New layouts and exports are prepared
for review; authorization to create them is separate from visual acceptance.

SVG masters contain paths with no external image or font dependencies. The manifest
records formats, dimensions, file sizes and SHA-256 hashes. Rebuild instructions
are in `source/README.md`; the archive includes the master and export script.
Review small icons on each actual browser/device and agree printer-specific color
conversion and a physical proof for press work. Applying the palette to working
application screens still requires visual and accessibility verification.
